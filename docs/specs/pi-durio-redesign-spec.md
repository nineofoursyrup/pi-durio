# pi-durio 改版规格

规格标识：`PI-DURIO-REDESIGN-SPEC-r1` · 2026-10-14（Asia/Shanghai）

修订：2026-10-20 视觉修正 r1（#92 首次逐屏确认后由用户决定）改写 U1 的标识与最近会话选择、U6 的摘要行数与配色，U10 增加间距规则。同日视觉修正 r2（#92 第二次逐屏确认后由用户决定）把 T1/U10 的输入框改为圆角整框，U10 增加顶部留白、键位配色并写明弹层下的底色，U3、U4、U6、U8、U9 补充配色与版式。

本规格以 Claude Design 稿《pi-durio TUI》的 9 屏（1a–1f、2a–2c）为准，汇总 [pi-durio TUI 改版决策地图](https://github.com/nineofoursyrup/pi-durio/issues/34) 下 20 张已关闭票（#35–#49、#59–#63）和 [改版验收与交接边界](https://github.com/nineofoursyrup/pi-durio/issues/50) 的决定，作为改版实现与验收的入口。它收录首版规格 `PI-DURIO-V1-SPEC-r1` 的全部条款：改动的条款在原位置重写，未改的照录；另加 U 组按屏条款。发布后本规格是 pi-durio 唯一现行的合同；r1 保留为首版验收的依据，不再修改。设计决策完成不表示改版已实现、通过验收或获得日用接受。

## 读法

- **优先级**：本规格正文与各票 resolution 不一致时，以本规格为准。本规格未写到的细节（逐元素表格、文案、取数位置）以对应票的 resolution 为准；同一点被后来的票修订过的，以最后一次修订为准（见各票“对已定各票结论的修订”）。仍有实质矛盾时，指出具体来源并停止受影响路径，不静默取舍（A5）。
- **编号**：S1–A5 沿用 r1 编号，各票中“修订 T1”等引用仍然有效。U1–U9 依次对应 1a、1b、1c、1d、1e、1f、2a、2b、2c；U10–U14 为跨屏条款。
- **来源标注**：每条末尾标〔来源票 · 屏〕；〔r1〕表示照录首版条款。照录条款中的“首版”指首版起已有的行为，改版沿用。
- **示意数值**：设计稿和本规格例子中的号码、金额、计数都是示意，不是需求。

## Problem Statement

首版（候选 `f26ae8f`）已于 2026-10-11 日用接受。日常使用中，TUI 的信息与操作方式成了主要负担：引用会话、run 或报告只能复制 UUID；费用按 pi-ai 目录的美元高峰价估算，不分峰谷，与人民币账单对不上；状态行看不出上下文用了多少；每受理一个任务就是一组新身份，看不出哪些任务属于同一段工作；improve 选择要手写 JSON 写明改动全文、检查和预算；指标、trace、eval 分散在多个只读面板，trace 包在 JSON 里，eval 视图不能启动或停止批次。

使用者为此做了 9 屏 TUI 设计稿，要求按它改版：日常操作尽量在视图中选择完成，命令参数留给 agent；同时保持首版的正确性、授权、原文保留与轻量约束，不为还原设计而增加不必要的自有代码。

## Solution

按设计稿改版 TUI，并修订与之冲突的合同。ADR-0001–0003 不重开，不新建 ADR。

- **跨屏口径**：带类型前缀的显示号，命令都接受；费用一律按宿主附带的 DeepSeek 人民币价目分峰谷估算；状态行显示 `ctx ≈… / 1M`。这三项已由先行切片 #51 实现（Draft PR #58）。
- **会话**：会话是上下文链，由已有记录推导。欢迎屏列最近会话，`resume` 与会话列表可以接续，已完成的会话可以跨执行版本接续。
- **界面**：Terminal.app 中的视觉系统分三档；键位分会话屏与全屏视图两层；能用视图选择完成的操作都有视图，带参数时只读操作直接打开，计费或写记录的操作只预填确认框。
- **各屏**：恢复核对改为按项处置，只做宿主检查；improve 候选附带替换片段和结构化检查，从视图发起和选择；`/stats` 分指标与本机实测两个页签；trace 为瀑布视图；eval 视图可以启动、停止批次和重评分；CLI 入口改为 `pi-durio`、`resume`、`show`。
- **首版记录**：不补录、不迁移，按已有事实呈现。

## User Stories

1. As a local developer, I want pi-durio to edit my project and run relevant checks, so that I can complete everyday coding work with a small, maintainable tool.
2. As a terminal user, I want clear task state, current-task steering and explicit follow-up requests, so that I can guide work without confusing queued input with executed actions.
3. As a user returning after an interruption, I want read-only recovery checks and explicit handling of uncertain side effects, so that unfinished work does not silently repeat or change execution conditions.
4. As a user inspecting past work, I want complete acquired originals and bounded queries, so that I can trace outcomes without loading all history into memory or the model.
5. As a user managing long sessions, I want automatic and manual context compaction plus explicit archive and cleanup controls, so that I can manage context and storage while protecting recovery and fixed evidence.
6. As a user evaluating reliability, I want success, cost, time, intervention, regression/rework and failure reports with honest denominators and missing-data states, so that I can judge results without extra mandatory feedback.
7. As a user testing a change, I want fixed cases, independent scoring and bounded fresh comparisons, so that improvement claims are supported by valid evidence.
8. As a user requesting improvement, I want a few evidence-backed candidates or an honest no-candidate result, so that I can decide whether a change is worth making.
9. As a user selecting candidates, I want execution, validation-only, deferral and persistent suppression to have distinct effects, so that only my selected scope is carried out.
10. As a user changing agent behavior, I want verified content, explicit activation and safe version boundaries, so that my edits and unfinished work remain protected.
11. As the daily user, I want real provider and Terminal validation plus reproducible resource measurements, so that I can explicitly decide whether each delivery is ready for daily use.
12. As a terminal user, I want short typed display numbers that every command accepts, so that I can refer to sessions, runs, reports and plans without copying UUIDs.
13. As a user billed in RMB, I want peak/off-peak RMB estimates and context usage in the status line, so that estimates match my bill and I can see how close compaction is.
14. As a returning user, I want sessions as context chains that I can list, open read-only and continue across processes and builds, so that I can pick up work where I left it.
15. As a user handling an interrupted run, I want per-item recovery choices based only on host facts, so that I decide each unknown without the tool pretending to verify external targets.
16. As a user selecting improvements, I want candidates that carry the exact change and checks and can be chosen entirely in a view, so that what I authorize is exactly what runs.
17. As a user inspecting quality and cost, I want metrics, trace, eval and local measurements as navigable views with drill-down and export, so that I never need JSON arguments or scattered panels.

## Implementation Decisions

### S — 范围、复用与工程起点

- **S1 平台与目标。** 承诺用户本机 macOS arm64 的 Node CLI 日用；验收终端为 macOS Terminal.app。优先减少自有维护代码，再据测量优化体积、冷启动、内存与观测开销。无预先批准的 LOC、MB、ms、RSS、token 或费用硬阈值。产品内的本机实测（`/stats --self`）只报告当前进程、已有记录和构建清单可得的数值，不在产品内制造负载、重复启动或写测量记录；受控测量在产品外进行（A2）。设计稿隐含的新能力按本条逐项裁剪，裁掉的列在 Out of Scope。〔#49 · 2c〕
- **S2 公开上游。** 使用 durable 的公开 Harness、ExecutionEnv、storage、tools 与测试接缝，不依赖官方 demo 的 monorepo 私有导入，不重写 loop、调度器、恢复状态机或 usage 聚合。Pi 精确 `1.1.0` 是待实际安装验证的候选基线，直接依赖精确固定、传递解析由 lockfile 固定，记录发布工件身份；升级显式进行，不预先维护 fork。研究源码 SHA 与 npm 构建来源不同，相同版本号不能证明源码相同。〔r1〕
- **S3 共用执行。** TUI/headless/eval 通过同一受控业务入口，复用 read/write/edit/bash；搜索和检查先走已授权 shell。宿主连接模型、工具、能力、所有权与记录；UI 不持有绕过宿主检查的原始 Harness。不同场景可以使用不同能力配置，headless 不降低恢复和权限要求。交互入口（无参数 `pi-durio`）默认授予 coding 能力（read/write/edit/bash），`--read-only` 收窄为只读；`resume` 沿用链尾授权；headless `run`/`control` 仍须显式 `--coding`。〔#46 · 1f〕
- **S4 模型与认证默认值。** 复用 DeepSeek provider，初始 API ID 为 `deepseek-flash`、协议为 `openai-completions`、默认官方端点为 `https://api.deepseek.com`。从外部环境 `DEEPSEEK_API_KEY` 读取凭据，缺失或失效明确报错，不静默换服务。模型和有效参数在任务开始时固定并记录，未另指定参数采用所选 provider 支持的默认值。请求模型、可取得的返回标识和后端指纹分别记录，别名不证明权重不变。宿主认证、配置及错误处理不主动将凭据值加入 prompt、会话、版本材料、trace、错误详情或报告；偶然包含敏感值的运行原文按 E1/E10 区分保真保存与派生脱敏。〔r1〕
- **S5 工具环境。** bash 不默认继承完整宿主环境，使用公开 prepare/ExecutionEnv 接口选择必要构建环境；模型 API Key 不默认传给工具子进程。额外项目变量通过显式配置增加，只记录变量名及配置版本。可信本机执行仍具有当前用户可用权限，不承诺同用户凭据绝对隔离或将访问限制在项目目录内。〔r1〕
- **S6 本地最小形态。** 单进程与一个活动工作区写入者为起点；观测默认本地。首版没有独立遥测服务、第二套数据平台或通用工作流引擎。物理模块、表、字段、命令及页大小按公开接口和实际测量选择；逻辑对象不要求各占一张表或一个类。〔r1〕

### R — 可信本机执行、所有权与恢复（ADR-0001）

- **R1 授权落点。** 普通 coding 在已授权任务内连续完成修改和必要检查，不增加逐命令审批。模型输出、项目文本、历史材料和工具输出不能扩大授权。能力约束落实在实际工具执行/环境边界，覆盖新调用和恢复重放；`beforeTool`、prompt、cwd 或 replay 标志都不能独立承担此保证。四个工具沿用默认 unsafe，不因名称是 read 就宣称 safe 重放。〔r1〕
- **R2 所有权。** 可写打开数据根、session storage 及 `Harness.open()` 前取得相应 owner lock；同一 storage/data root 的第二写入者在写入前被挡住。另对声明工作区取得写入者锁，规范化实际路径并识别别名、子目录和登记的重叠非 Git 根目录。锁冲突显示持有者及恢复方法；切换工作区先取目标锁。锁只约束遵守协议的实例，不能覆盖外部编辑器修改，也不使不同 worktree 的共享 Git/外部资源自动隔离。陈旧锁使用成熟 owner/heartbeat 核对，不能仅凭 PID 消失或超时夺锁；残留进程未确认结束时保留不确定状态。〔r1〕
- **R3 查看与执行分离。** 历史查看必须真正只读，不调用会协调写库的普通 Harness open，不触发模型、工具或调度。可写打开 storage 及 Harness 前，以只读路径检查原执行内容是否可取得、兼容性、当前授权、工作区与全部 Harness 残留任务；显式继续仍须符合这些条件，运行中实际能力边界持续生效。resume、submit、compact、wait、abort 等可能启动调度的路径都经过同一宿主边界；管理旧工作不能顺带放行其他 pending。`pi-durio resume` 与 `pi-durio show` 只打开界面，不取锁、不调度；继续旧工作仍经同一宿主边界和恢复确认。〔#46 · 1f〕
- **R4 退出与中止。** 退出停止接收新工作，请求取消并等待受管执行清理、存储关闭后再释放所有权，保留可恢复工作；停止任务持久化中止意图，不作为普通 pending 自动续跑。二者都不回滚已发生的修改，不承诺远程请求/所有子进程已停或退出后后台运行。取消等待不等于任务取消；无法确认清理完成时记录未知。〔r1〕
- **R5 恢复核对。** 已提交结果读取复用，不重做、不重复计量。存在 intent 而结果缺失、可能已有副作用时，先进入受限只读核对；核对期间阻止新副作用及模型提出的等效新调用，任意 shell 不因命令看起来只读而放行。核对内容固定为宿主检查（记录、执行版本、授权、锁、其他会话的 pending），不运行命令、不调用模型、不核对外部目标状态，也不提供幂等判定；只依据持久结果确认已完成。证据不足时呈现逐项未知、宿主证据与可能重复的影响，由用户处置：整体“重新核对（只读）”，按项“视为已完成”或“重试”，整体“结束旧工作”；不提供 `skip`。按项处置要求执行版本、当前授权与锁检查通过，全部选完后一次提交，覆盖全部未知。视为已完成的工具以及宿主已有结果、durable 未提交的工具，续跑时按原授权进行，宿主拦截工具与参数完全相同的新调用并告知模型该操作已完成；参数改写过的等效调用无法机械识别，属于可信本机执行接受的风险。核对结论和用户决定追加记录，原 interrupted/unknown 不改写为成功；首版记录中的 `skip` 照录为“跳过（首版处置）”。〔#43 #63 · 1c〕
- **R6 执行版本。** 执行版本涵盖 build、依赖 lock、工具/扩展、有效指令及模型配置，保留实际可取得内容或经验证的不可变工件；只有 hash 不代表可恢复。行为相关版本变化不自动接管旧 pending；原组合可取得且当前授权和兼容性满足才恢复，否则由用户结束旧工作并显式开新任务。凭据轮换、纯显示设置不机械算作行为版本变化；schema 迁移成功也不授权跨版本续跑。已完成会话的上下文接续不属于旧 pending：新任务按当前执行版本运行，授权沿用链尾；构建与依赖内容、Node 与平台、执行配置任一项不同即算版本已变，由已有记录推导并标示，不新增记录。冻结的排队项和冻结的 improve 批次仍属旧 pending：版本不一致时不按原身份继续，follow-up 与排队的 improve 分析可以撤回后作为新任务重新提交。〔#62 · 1b 1f〕
- **R7 headless 与请求中断。** 需用户决定时先持久化原因和可选项，以可识别的非零退出状态和机器可读结果结束，不无限等待或假定同意。后续显式决定仍须恢复检查。模型重新请求形成新尝试，可能新增费用；沿用有效授权和预算，未返回或未提交 usage 保留 unknown/partial。〔r1〕

### T — TUI、输入队列与恢复交互

- **T1 布局。** 界面分两层：会话屏（1a 欢迎、1b 主会话、1c 恢复核对）和全屏视图（1d、1e、2a、2b、2c、帮助及 U13 的面板）。底色、颜色、字形与框线按 U10。会话屏主区只显示当前任务，前序任务用一行提示；底部依次为队列行、状态行、圆角整框的输入框和底栏。头部与底栏显示工作区、会话与 run 的显示号、模型、上下文用量与费用估算，已知与未知用量分开（E6）。工具行默认折叠，摘要只写系统掌握的事实，不解析命令输出；失败与截断在折叠时可见；点击切换单行，Ctrl+O 展开或折叠全部；完整原文与 trace 打开 2a。鼠标支持滚动、选文、点击展开与选中，核心操作都有键盘入口。帮助是 `?` 或 `/help` 打开的视图；`/` 弹出命令补全（含子命令与选项值），`@` 弹出文件补全、只插入路径；不设 F2 菜单。能用视图选择完成的操作都提供视图选择，命令参数供 agent 使用：不带参数时打开视图；带参数时，只读操作直接打开对应层，会产生费用、写记录或改变保留状态的操作只预填确认框；参数有误时不打开视图，只在状态行报错并列出可用值。各屏布局见 U1–U9、U13，通用状态、确认框与窄终端规则见 U12。〔#40 #41 #42 #44 #47 #48 #59 #60 视觉修正 r2 · 全部〕
- **T2 状态与有界显示。** 区分运行、等待输入、重试、恢复核对、中止中、退出中、已中止、完成，事实来自 runtime 提交状态。状态含义由字形承载（U10），不只靠颜色；运行态 spinner 为 braille 10 帧、80ms。“第 M 轮”是本任务 run 中发往模型的任务请求序位，不含压缩请求，重试另算一轮；运行计时从当前执行段开始（`run.started`，恢复后为 `recovery.started`），不计中断时间。历史窗口读取、大输出分页，区分显示截断、送模截断、源原文本身不完整和原文不可取得；原文逐项标取得状态（E2）。上滚后暂停跟随，可显式回到底部；新输出不夺焦点或覆盖草稿/展开态；打开中的 trace 与 eval 视图随新记录追加。加载态只用于异步操作，超过 200ms 才显示；“没有”与“出错”分开写，不用 0 或 N/A 表示没有。小窗口按 U12 的固定顺序收起；最小 40×12（首版已在 Terminal.app 验收），更小时提示窗口过小。〔#40 #41 #47 #59 · 全部〕
- **T3 当前任务和后续请求。** 空闲 Enter 提交新任务；忙时 Enter 为 steer，在当前工具轮次边界接入，不中止已发出的操作。follow-up 有明确入口并等待当前工作结束，`Ctrl+X → Enter` 为默认键位。显示受理、待接入、已接入；已接入的 steer 在主区接入位置显示为标 `steer` 的用户消息块。待接入项可撤回，竞争按 runtime 已提交事实判定，请求已接入时显示“已接入，未撤回”。撤回入口：会话屏输入为空时按 Backspace 撤回最新一项（距上一次 Backspace 不足 500ms 不撤回）；点击队列行的“撤回”只撤回该行；队列视图 `w`；`/withdraw q-号`。撤回的文本不放回输入框，可按 ↑ 从输入历史取回。steer 归当前任务，follow-up 接入后开始自己的 run。improve 分析或 eval 批次运行期间，会话屏输入照常编辑，Enter 保留文字、不受理；分析结束后，下一次 Enter 接续当前会话。〔#41 #42 #48 #59 #60 · 1b〕

### V — 手动 eval 与改善判定（ADR-0003）

- **V1 最小 eval。** eval 视图（2b）与 CLI `eval run` 两个入口，共用同一个顺序 runner、少量固定 TypeScript/Node 案例与本地可读/机器可读报告，共用 runtime 和现有证据。TUI 只启动已固定的计划，新建计划仍由 `eval plan` 和 improve 的 fresh 对照产生。runner 可在 TUI 进程内运行，启动前核对宿主文件与计划固定的内容一致，被测 runtime 只在受限侧运行；其他进程运行的批次在 TUI 中只读跟踪。四类任务为局部修复、多文件小改动、已修复问题回归、不应改动的反例，可共用 fixture，无测试数量配额，也不限制产品只能处理 Node 项目。每例固定输入、可取得初态、可改范围及真实验收规则；历史聊天或 hash 不替代 fixture。公开回归集可参与开发，暴露过的案例不继续称未见独立集。〔#48 · 2b〕
- **V2 计划。** 批次执行前固定目的、baseline/candidate 内容、一个主目标、保护行为、目标案例与仅保护案例、fixture/lock/dirty 输入、grader/门槛内容及身份、两侧版本/环境/缓存/模型配置、所有 case×版本×重复的身份/配对/次序、重试限额、超时、调用/用量限额和费用口径。每批展示这些范围；完整 eval 命令或 improve 选择已包含授权则不重复确认。缺有效限制不启动付费批次；无判定门槛可诊断但不能正式判改善。扩大范围或预算需新决定。TUI 启动确认框展示的就是这些范围，以及按高峰价计算的人民币预算上限和截止时间；命令参数只预填，仍须确认；计划截止时间已过时不能启动。一份计划只运行一次，停止后不续跑。新付费计划默认以宿主价目的人民币高峰输出价为统一单价上界，并记录价目版本；首版已固定的美元计划按原币种显示、不重算。〔#39 #48 #51 · 2b〕
- **V3 独立试次。** 两侧同初态和预算、不同 session/空间，按预先记录的顺序交替先后；每 trial 新建环境，不带入上次答案、文件或进程。独立 HOME、临时区及可写缓存，只复用经校验的只读依赖。准备、任务、评分时间分别记录，用户等待不算模型活跃。固定 seed 不保证服务端确定性。重新评分追加判断而不改 outcome；实际补跑新建 trial 并关联首败。〔r1〕
- **V4 正式隔离。** 选一种现成隔离能力并验证，不自研通用沙箱/多后端。可信外层 runner 持有原 fixture、计划、grader、隐藏预期和报告；被测 runtime、工具、依赖与产物全部在受限侧，修改 runtime 也不能控制可信评分。限制宿主 HOME/凭据、其他 trial、共享可写 Git、历史答案、控制 socket/进程通道与任意网络；模型调用由可信宿主按预算中介，密钥不交被测代码。依赖预备，额外网络入计划。worktree/session 分离、prompt、环境清理或 hash 检查均不足以证明隔离；未落实边界的本机试跑只标诊断，不能暴露隐藏资产或声称正式改善。〔r1〕
- **V5 产物和评分。** 评分前确认执行及子进程结束、固定最终产物；只导出声明范围普通文件，不跟随外部链接、不执行导出内容。需运行产物时在同样受限的评分执行区，隐藏预期留在可信侧比较，不以候选修改的测试或“通过”日志为准。实际越界、污染或无法确认边界有效使相关 trial 无效并停止受影响后续工作。grader 故障是无法评分，不自动把候选判 FAIL；可靠必要要求失败可判 FAIL，不必等全部检查。〔r1〕
- **V6 预算与失败。** 默认不自动重开失败 trial；请求重试受计划限量并计入原 trial。开始新 trial/请求/重试/compaction 前检查额度和时限，重启不重置预算或截止点；计入两侧、失败/重试、压缩和评分成本。未知用量只有在可证明在途上界仍约束预算时才继续，否则暂停新请求；在途请求的上界按高峰价计算。取消不证明退款或账单停止，残留进程未确认结束不复用空间或开受影响试次。失败、超时、取消、需求变更、预算停止、服务故障、grader 故障、无效和未运行分别留在全部计划中，保留首败；不能重跑到成功再覆盖。〔#39〕
- **V7 验证按影响选择。** 无行为文案/精确去重做一致性和加载检查；确定性 bug 做实际回归；启动、内存、体积、查询问题做相应基准；模型策略/prompt/skill 的行为或成本/延迟变化才做 fresh 对照。复用适用的既有检查，不强制每次全量 eval、第二 reviewer 或新测试框架。判定时间/调用/用量须由可信 runner/provider 边界或独立观测提供，候选 runtime 自报只能辅助。2b 中打开的 trial trace 展示受限侧导出的原文，标“受限侧自报 · 仅供诊断”，在宿主上只读打开其副本；用量与金额取宿主中介记录，按请求序位对应，对不上时并列并标明不一致；原文打不开时只列宿主记录并注明原因。〔#48 · 2b〕
- **V8 效果规则。** 任务达标与效果分开，先正确性/授权等硬约束，再保护项与主目标，不能用综合分抵消错误。随机行为按预定计划重复，无次数/阈值依据可先诊断，不能看完结果改门槛。逐主目标案例、逐配对定义差值 d（正为更好）及预定最小收益 δ>0：费用、请求数、token、耗时的 d 为以 baseline 为分母的相对值，baseline 为 0 的配对不可比、不进入判定；task-pass 的 d 为通过与否之差；首版旧计划保留绝对 δ 并带单位显示。软保护项另定容忍度，口径与 d 相同；硬约束零退化容忍。改善要求全部计划完成且有效、候选及保护项达标、每个主目标配对 d≥δ；成本/延迟改善还要求两侧任务效果达标且完整可比。无明显差异要求全部计划完成且有效、硬约束与保护项通过，并且每个主目标配对 −δ<d<δ。有效证据证明新增硬回归即可判退化并停止；软退化要求完成有效比较，主目标每对 d≤−δ 或对应保护项重复一致越过容忍度。其余为证据不足，包括未完成、污染、缺口、单次随机成功、无阈值或方向不一致。先判已证实退化，再改善/无明显差异；已发现硬失败始终保留，无法归因新增则报告不达标及效果证据不足。〔#48 · 2b〕
- **V9 报告与规则修订。** 全部计划 trial、执行状态、outcome/评分/版本/初态/隔离证据与原因可追查，两侧列计划/启动/正常完成/可评分/通过数和有效配对。通过率=通过/可评分，完成率=正常完成/计划，覆盖率=可评分/计划，零分母 N/A；可评分可包含明确 FAIL 的错误/超时，不是正常完成的子集。显示总耗时/费用、缺失与配对差异，不只挑成功。显示中字形只表达有效性与评分（✓ PASS、✗ FAIL、? 无法评分或未取得结果、! 无效、⠹ 本 TUI 正在运行、· 未运行），超时、取消、预算停止、服务故障写在说明；预算写“含两侧、失败与压缩”；eval 费用单列，不计入 1e。grader 独立版本化，可对相同两侧产物重评分；TUI 中的 `r` 只用同一版本 grader 重评分，新版本 grader 经 improve 的 eval 资产候选或 CLI `eval grade --spec` 引入，improve 发起的计划不在 2b 重评分。改变初态、任务或行为须新试验，不能同时改候选与 grader 来证明原候选有效。内容和必要证据固定保留，结论仅限本批案例/环境，不外推普通全权限执行或总体稳定性。〔#48 · 2b〕

### I — improve 的建议、选择、执行与生效

- **I1 触发和受限分析。** 一个内置 improve，从 improve 视图的“新建分析”或 `/improve new` 经启动确认框发起，普通 coding 不自动跑 critic。确认框写明“分析不执行任何候选”及可看文件数与省略数，用档位选择：取证范围（仅本会话 / 本会话 + 近 7 天同类 / 本会话 + 近 30 天同类，默认 7 天）；预算上限（标准为 ≤16 请求、单次输出 ≤32k tok、总计 ≤2.16M tok、≤10 分钟，加大为各项翻倍，按最坏情况预留折算人民币上限）；附加来源（已登记的自身源码与 eval 资产，默认不勾）；分析重点（选填）。“本会话”指上下文链中的全部 run，“同类”指同项目、同任务类型，最多 10 条。默认可看本会话各 run 实际读过或改过的项目文件，以及本项目当前由 improve 启用的 prompt、skill 与配置；数量与大小沿用首版上限，超出时保留最近用过的并写明省略数。忙时确认后独立排队，绑定原会话/项目，开始时固定取证截止点，不随 UI 切换目标。取证先当前会话，按需再取同类摘要与必要片段；只开放范围内摘要、脱敏证据及相关源码/配置视图，不给任意 write/edit/shell；报告由宿主保存。达到上限时保留不完整报告，不自动加预算。默认最多 5 候选、无最低数量，零候选合法。分析期间主区留在当前会话；完成后只在主区插一行通知，不自动打开 1d。〔#44 #59 · 1d〕
- **I2 候选合同。** 每项有稳定 ID/revision（候选显示号在报告内有效，报告外须带报告显示号）、问题/目标/适用版本、可追查事实和必要成功反例、证据覆盖/缺失及分开的原因假设、最小动作/可改范围、验证/预算/保护项、风险/回退、是否写回或启用及条件/时机、依赖/冲突。检查当前机制和历史决定，不因缺某 skill/CI 自动建议安装，不虚构收益；缺目标或验证条件可提补充验证候选，不能用“全部优化”代替范围。可执行候选必须附声明范围内文件的替换片段（宿主应用到取证时的基线，得到改后全文）和带数值预算的结构化检查（命令或 fresh 对照参数）；缺少可执行内容或目标未经核对的标为“仅建议”，只能暂缓或不再建议。revision 覆盖内容本身，用户选择授权的就是卡片上的这份内容，候选文本本身不授权。冲突即同批互斥。〔#39 #44 · 1d〕
- **I3 可改对象。** 明确的项目文件、agent 配置、prompt/skill、pi-durio tools/runtime 源码以及独立 eval 资产均可成候选。自身源码与 eval 资产须经来源登记（首次输入一次路径，宿主核对实际内容/build 与目标对应后记入数据根）才能勾选使用，每次分析开始时重新核对；名称或 remote 相同不足以证明，缺少条件保留建议，不寻找同名目录或改安装包。凭据不作为候选材料。eval/grader 变更独立处理；Markdown 行为改动不因后缀而降为纯文案。〔#44 · 1d〕
- **I4 结构化选择。** 1d 中逐项选“执行声明范围”“仅验证”“暂缓”“不再建议”，默认不选。组合、顺序、临时目录、基线与 runtime 身份、总预算与时限由宿主从候选推导；汇总框写明计数、执行计划、总预算（以人民币价目版本固定，在途请求按高峰价）、绑定信息、停止规则与授权提示，一次明确提交。冲突、依赖项未选、组合内模式不一致、报告或基线已变化时不能提交并列出原因；只选暂缓或不再建议时只记录决定。headless 用等价结构化决定；TUI 命令参数只预填，仍须在汇总框确认；自由文本只补充意见，不推断执行同意。选择绑定报告/候选 revision、目标/基线、模式和声明步骤；刷新或实质漂移（含基线变化）使旧选择失效，须重新分析，宿主不把片段套到新基线。先可靠保存决定再动作，同一批次重复提交只读已有状态，不重复执行；未选项或依赖不自动执行。每个候选在一份报告内只决定一次，例外是仅验证已通过的候选可再选执行，重新验证后写回，预算另算。首版报告在改版中只读，不进入“待选择”，同一候选的多次决定以最后一次计数。〔#39 #44 #63 · 1d〕
- **I5 仅验证与准备。** 可在声明临时副本/可回退内容中构造候选和执行预算内检查，保存产物及证据，但不写回正式目标、切默认或因通过而启用；默认不含外部写操作。编辑即生效的配置/规则/skill 也先在临时目标准备，不能先覆盖再称未启用。临时目录不是权限沙箱；不强制所有项目有 Git。无法在选定范围安全验证/写回时保留候选和阻塞。〔r1〕
- **I6 抑制。** 暂缓不原样立即重提，只有条件/证据实质变化才说明原因再提；不再建议在明确项目或配置目标范围内持续抑制同一问题，直到用户主动恢复，换 ID/措辞、普通升级或新增同类记录不解除。不扩展为全局禁令，不删除历史失败/原文，不另建语义检索服务。恢复抑制的原因为预设选项（条件已变化 / 当时判断有误 / 想重新评估），另可选填补充。〔#44〕
- **I7 顺序、组合与失败。** 一个提交批次和有序清单，复用写入者约束。顺序按依赖做拓扑排序，没有先后要求时按候选号。无相互影响项可逐项执行；有依赖或改同一目标的项自动合成组合，组内模式须一致，组合验证，单项通过不代表组合通过，组合效果不分别归因。不兼容组合要求调整选择；范围内必要步骤连续完成，扩大动作/预算才重新决定。失败、取消、未知副作用、记录失败或基线失效时默认不启动剩余项；保留已完成/失败/未运行。独立完成项不自动回滚，未完成组合不正式写回/启用，已发生部分写入进入核对。仅因批次停止而未运行的独立项，前提/原授权/预算/执行版本有效时可显式继续，普通消息不解冻；执行版本与批次不一致时只能回退或新开分析。〔#44 #62〕
- **I8 验证和启用。** 写回前再次核对用户编辑、目标与基线；启用内容必须就是验证内容，验证 A 不能复制 B 后称通过。性能主目标必须证明预定收益才启用，检查通过但无明显差异/证据不足仍不启用，不自动加样本或事后改称“清理”。非性能候选按 V7 的影响范围选择直接检查、真实回归、基准或 fresh 对照，仍保留必要保护项；确定性修复与无行为变化清理不额外强制模型 A/B。配置/prompt/skill 可设后续新任务默认；tools/runtime 产出已验证可启动新 build，启用仅面向后续显式启动的新进程，当前进程不自替换、自重启。build 生成、默认设置、实际观察生效分别记录，旧 pending 不热迁移。〔r1〕
- **I9 回退与授权。** 候选先说明可行回退、保留旧内容，缺能力或不可逆副作用明确说明。显式回退以候选所在的组合为单位，确认框列出要恢复的文件，原因为预设选项（效果不如预期 / 引入了新问题 / 不再需要）另可选填补充；回退前核对当前内容和后续用户编辑，不用 reset/clean 或整目录覆盖擦除他人工作；回退不逆转既有副作用。防重复执行的请求号由宿主生成。正式写回失败只有已声明补偿、目标精确对应本批产物且无未知外部副作用时，才在原授权内撤销本批写入。执行候选不隐含提交、推送、发布或数据清理，不允许被托付代码改宿主授权/预算/效果判断。〔#44〕

### M — 六项 LLMOps 指标与最少人工反馈

- **U14 首版记录与跨版本。** 首版记录不补录、不迁移，按已有事实呈现，个别事实缺失时显示“未记录”，不显示 0，也不推断。**分叉**：同一 run 被接续多次时，按受理先后，最早的那次接续留在原会话，其后每次接续各开一个分支会话；每个会话仍是一条线，每个 run 只属于一个会话，分叉点及之前的 run 属于原会话；分支会话的显示号取其第一个任务的 sessionId，任务 N 沿用上下文链深度（分叉点为任务 N 时，分支的第一个任务是任务 N+1），链尾为该会话的最后一个任务；`resume`、`c`、退出摘要“继续”对分支会话接续分支的链尾；在分支会话中发起 improve 时，“本会话”仍指上下文链中的全部 run。改版不禁止 headless `run --context-run` 指向非链尾 run 显式开分支；TUI 的 `c`、`resume` 与空闲 Enter 只接续链尾。**导入前失败**：在 Harness 打开、写下 `context.imported` 之前就失败或中止的 run 自成一个会话，不加标注，不补写接续源。**首版恢复记录**：旧 `skip` 显示为“跳过（首版处置）”，用户当时的说明照录；只读续跑与被拒写操作按 U7 照录；不新增术语，不影响当前可选的处置。**首版 improve 报告**：按报告格式识别（候选没有替换片段与结构化检查），只读，不进入“待选择”，`/improve ir-号` 遇到首版报告时打开历史报告详情；唯一可用的操作是回退已写回的组合，冻结批次的继续不可用；未决候选卡头标“未决 · 首版报告不能选择”；首版仅验证已通过的候选不能再选执行，要做须新开分析；首版候选 `R1…R5` 按数组位置映射为 `C-01@r1…C-05@r1`；同一候选的多次决定以记录顺序中的最后一次为准，卡头注明“首版另有 K 次决定”，展开后按时间列出全部决定及结果；报告末尾的回退项列出所有仍有效的写回；首版写下的建议抑制照常列出、可以恢复。**非 UUID 身份**：首版与改版中由用户指定的 improve 报告号、eval 计划号与排队请求号按 E3 取 SHA-256 前缀，详情头部写一次“原 id …”。**跨版本**：首版会话在改版构建下可以接续，第一个改版任务标“执行版本已变”；首版冻结的 follow-up 按 T4 撤回后作为新任务提交，冻结的手动压缩不可重新接入，冻结的 improve 批次不能继续、可以回退；首版旧 eval 计划的美元预算与绝对 δ 按原单位显示，其 trial trace 照常可打开。**先行切片的增补**：#51 已实现的显示号与金额规则沿用；改版另需补上 `q-` 前缀、会话显示号取会话第一个任务的 sessionId，以及队列、恢复、历史等面板与 improve 报告 `Target` 行改用显示号（PR #58 列出的已知偏离）。〔#46 #48 #51 #60 #61 #62 #63〕
