# pi-durio 首版实现规格

规格标识：`PI-DURIO-V1-SPEC-r1` · 2026-10-09（Asia/Shanghai）

本规格汇总 Map #1 下 #2–#9 已确认并关闭的设计决策，作为首版实现与验收入口。设计决策完成不表示产品实现、真实模型验收、日用接受或发布完成。各完整 resolution 为对应决策的来源；链接见 Further Notes。下文沿用已确认合同及随合同接受的可逆默认值，不将工程默认值冒充用户逐项指定。

## Problem Statement

使用者需要一个可以在自己 Mac 上日常处理 coding 工作的轻量 agent：能修改项目、运行必要检查、解释失败并可靠恢复，也能查清任务经历了什么、用了多少资源、哪些结果有证据支持。仅有一段聊天、模型自报完成或最后一次成功输出，无法支持长期质量判断。

使用者还需要显式调用 `improve`，从真实运行证据中获得少量可选改进，仅执行自己选中的范围，并验证是否有效。产品应尽量减少自有代码、依赖和长期维护负担，同时保留正确性、可追溯和用户控制；不能通过隐藏失败、删除原文或放宽权限来换取“轻量”。

## Solution

交付 macOS arm64 本机 Node CLI，使用 TypeScript、pi-durable、pi-ai、pi-tui 和本地 SQLite，初始实际使用路径为 DeepSeek V4.1 Flash（`deepseek-flash`）。TUI、headless 和手动 eval 共用 runtime；普通 coding 采用可信本机执行，正式 eval 采用经过验证的受限环境。

首版完整路径包括 coding 与检查、TUI/headless、退出和恢复、完整运行原文、自动及主动上下文压缩、用量/trace/长期记录查询、六项 LLMOps 指标、手动 eval，以及 `improve` 的取证→候选→用户选择→执行验证→适用写回或启用→结果留存。内部实施阶段只能安排先后，不能删减这条路径。

复用上游已有 loop、持久化、恢复、compaction、工具和已知 usage；薄宿主落实授权、所有权、恢复前核对、证据保存、查询、eval 与 improve。先测量实际开销，最终依据技术验收、完整轻量报告及用户本机试用后的明确日用接受判断首版完成。

## User Stories

1. As a local developer, I want pi-durio to edit my project and run relevant checks, so that I can complete everyday coding work with a small, maintainable tool.
2. As a terminal user, I want clear task state, current-task steering and explicit follow-up requests, so that I can guide work without confusing queued input with executed actions.
3. As a user returning after an interruption, I want read-only recovery checks and explicit handling of uncertain side effects, so that unfinished work does not silently repeat or change execution conditions.
4. As a user inspecting past work, I want complete acquired originals and bounded queries, so that I can trace outcomes without loading all history into memory or the model.
5. As a user managing long sessions, I want automatic and manual context compaction plus explicit archive and cleanup controls, so that I can manage context and storage while protecting recovery and fixed evidence.
6. As a user evaluating reliability, I want success, cost, time, intervention, regression/rework and failure reports with honest denominators and missing-data states, so that I can judge results without extra mandatory feedback.
7. As a user testing a change, I want fixed cases, independent scoring and bounded fresh comparisons, so that improvement claims are supported by valid evidence.
8. As a user requesting improvement, I want a few evidence-backed candidates or an honest no-candidate result, so that I can decide whether a change is worth making.
9. As a user selecting candidates, I want execution, validation-only, deferral and persistent suppression to have distinct effects, so that only my selected scope is carried out.
10. As a user changing agent behavior, I want verified content, explicit activation and safe version boundaries, so that my edits and unfinished work remain protected.
11. As the first daily user, I want real provider and Terminal validation plus reproducible resource measurements, so that I can explicitly decide whether the complete first version is ready for daily use.

## Implementation Decisions

### S — 范围、复用与工程起点（#2、#3）

- **S1 平台与目标。** 首版承诺用户本机 macOS arm64 的 Node CLI 日用；首版验收终端为 macOS Terminal。优先减少自有维护代码，再据测量优化体积、冷启动、内存与观测开销。无预先批准的 LOC、MB、ms、RSS、token 或费用硬阈值。
- **S2 公开上游。** 使用 durable 的公开 Harness、ExecutionEnv、storage、tools 与测试接缝，不依赖官方 demo 的 monorepo 私有导入，不重写 loop、调度器、恢复状态机或 usage 聚合。Pi 精确 `1.1.0` 是待实际安装验证的候选基线，直接依赖精确固定、传递解析由 lockfile 固定，记录发布工件身份；升级显式进行，不预先维护 fork。研究源码 SHA 与 npm 构建来源不同，相同版本号不能证明源码相同。
- **S3 共用执行。** TUI/headless/eval 通过同一受控业务入口，复用 read/write/edit/bash；搜索和检查先走已授权 shell。宿主连接模型、工具、能力、所有权与记录；UI 不持有绕过宿主检查的原始 Harness。不同场景可以使用不同能力配置，headless 不降低恢复和权限要求。
- **S4 模型与认证默认值。** 复用 DeepSeek provider，初始 API ID 为 `deepseek-flash`、协议为 `openai-completions`、默认官方端点为 `https://api.deepseek.com`。从外部环境 `DEEPSEEK_API_KEY` 读取凭据，缺失或失效明确报错，不静默换服务。模型和有效参数在任务开始时固定并记录，未另指定参数采用所选 provider 支持的默认值。请求模型、可取得的返回标识和后端指纹分别记录，别名不证明权重不变。宿主认证、配置及错误处理不主动将凭据值加入 prompt、会话、版本材料、trace、错误详情或报告；偶然包含敏感值的运行原文按 E1/E10 区分保真保存与派生脱敏。
- **S5 工具环境。** bash 不默认继承完整宿主环境，使用公开 prepare/ExecutionEnv 接口选择必要构建环境；模型 API Key 不默认传给工具子进程。额外项目变量通过显式配置增加，只记录变量名及配置版本。可信本机执行仍具有当前用户可用权限，不承诺同用户凭据绝对隔离或将访问限制在项目目录内。
- **S6 本地最小形态。** 单进程与一个活动工作区写入者为起点；观测默认本地。首版没有独立遥测服务、第二套数据平台或通用工作流引擎。物理模块、表、字段、命令及页大小按公开接口和实际测量选择；逻辑对象不要求各占一张表或一个类。

### R — 可信本机执行、所有权与恢复（#3、ADR-0001）

- **R1 授权落点。** 普通 coding 在已授权任务内连续完成修改和必要检查，不增加逐命令审批。模型输出、项目文本、历史材料和工具输出不能扩大授权。能力约束落实在实际工具执行/环境边界，覆盖新调用和恢复重放；`beforeTool`、prompt、cwd 或 replay 标志都不能独立承担此保证。四个工具沿用默认 unsafe，不因名称是 read 就宣称 safe 重放。
- **R2 所有权。** 可写打开数据根、session storage 及 `Harness.open()` 前取得相应 owner lock；同一 storage/data root 的第二写入者在写入前被挡住。另对声明工作区取得写入者锁，规范化实际路径并识别别名、子目录和登记的重叠非 Git 根目录。锁冲突显示持有者及恢复方法；切换工作区先取目标锁。锁只约束遵守协议的实例，不能覆盖外部编辑器修改，也不使不同 worktree 的共享 Git/外部资源自动隔离。陈旧锁使用成熟 owner/heartbeat 核对，不能仅凭 PID 消失或超时夺锁；残留进程未确认结束时保留不确定状态。
- **R3 查看与执行分离。** 历史查看必须真正只读，不调用会协调写库的普通 Harness open，不触发模型、工具或调度。可写打开 storage 及 Harness 前，以只读路径检查原执行内容是否可取得、兼容性、当前授权、工作区与全部 Harness 残留任务；显式继续仍须符合这些条件，运行中实际能力边界持续生效。resume、submit、compact、wait、abort 等可能启动调度的路径都经过同一宿主边界；管理旧工作不能顺带放行其他 pending。
- **R4 退出与中止。** 退出停止接收新工作，请求取消并等待受管执行清理、存储关闭后再释放所有权，保留可恢复工作；停止任务持久化中止意图，不作为普通 pending 自动续跑。二者都不回滚已发生的修改，不承诺远程请求/所有子进程已停或退出后后台运行。取消等待不等于任务取消；无法确认清理完成时记录未知。
- **R5 恢复核对。** 已提交结果读取复用，不重做、不重复计量。存在 intent 而结果缺失、可能已有副作用时，先进入受限只读核对，阻止新副作用及模型提出的等效新调用；任意 shell 不因命令看起来只读而放行。依据持久结果、可靠目标状态或适用幂等机制确认已完成则不重做；确认未发生或可安全重试且授权仍适用才继续。证据不足时呈现具体未知、证据与可能重复影响，由用户选择处置。核对结论和用户决定追加记录，原 interrupted/unknown 不改写为成功。
- **R6 执行版本。** 执行版本涵盖 build、依赖 lock、工具/扩展、有效指令及模型配置，保留实际可取得内容或经验证的不可变工件；只有 hash 不代表可恢复。行为相关版本变化不自动接管旧 pending；原组合可取得且当前授权和兼容性满足才恢复，否则由用户结束旧工作并显式开新任务。凭据轮换、纯显示设置不机械算作行为版本变化；schema 迁移成功也不授权跨版本续跑。
- **R7 headless 与请求中断。** 需用户决定时先持久化原因和可选项，以可识别的非零退出状态和机器可读结果结束，不无限等待或假定同意。后续显式决定仍须恢复检查。模型重新请求形成新尝试，可能新增费用；沿用有效授权和预算，未返回或未提交 usage 保留 unknown/partial。

### T — TUI、输入队列与恢复交互（#4、#5）

- **T1 布局。** 全屏单列，主区会话、底部固定输入与简洁状态；显示工作区/会话、模型、必要键位、已知及未知用量。工具默认有限摘要，失败与截断在折叠时可见，按需展开 diff、输出、trace 和详情。鼠标支持滚动、选文、展开，核心操作有键盘等价入口；提供帮助与命令补全。
- **T2 状态与有界显示。** 区分运行、等待输入、重试、恢复核对、中止中、退出中、已中止、完成，事实来自 runtime 提交状态。历史窗口读取、大输出分页，区分显示截断、源原文本身不完整和原文不可取得。上滚后暂停跟随，可显式回到底部；新输出不夺焦点或覆盖草稿/展开态。小窗口保留必要操作，过小则提示；最小字符格范围由真实终端验证确定。
- **T3 当前任务和后续请求。** 空闲 Enter 提交新任务；忙时 Enter 为 steer，在当前工具轮次边界接入，不中止已发出的操作。follow-up 有明确入口并等待当前工作结束，`Ctrl+X → Enter` 为默认键位。显示受理、待接入、已接入；待接入项可撤回，竞争按 runtime 已提交事实判定。steer 归当前任务，follow-up 接入后开始自己的 run。
- **T4 队列冻结。** 请求中止、退出、失败或恢复核对后，未接入的 steer/follow-up 及未执行管理请求保存并冻结，由 runtime 阻止下一次普通提交将其偷偷接入。只有显式重新接入且恢复条件满足才解冻；已中止旧任务不能因此自动复活，新任务使用旧文本须明确重新提交。运行中 improve 为独立分析请求排队，不作为 steer、不全局更换当前任务工具集合。
- **T5 历史与恢复。** 查看其他会话只读，状态明确指向实际运行会话；历史视图禁止直接提交，先返回活动会话。中止写明目标，切换执行工作区仍检查所有权。恢复面板展示工作、最后确认点、未知、证据、动作影响；关闭面板只返回查看，不解除限制，也不能以通用确认弹框覆盖版本/权限条件。
- **T6 键位默认值。** 多行用 Shift+Enter / Ctrl+J，另提供反斜杠后 Enter 的换行回退，去掉转义反斜杠；Option+Enter 仅在用户自行配置 Meta 时可用。IME 组合或候选选择不误提交。运行中 Ctrl+C 请求中止；空闲第一次清输入并保留可恢复草稿、提示再次退出，未编辑/未换上下文的同键再按才请求退出。运行中中止不计为空闲 Ctrl+C 退出的第一次按键；停止/退出中连按不构成额外同意。Ctrl+D 在输入焦点且非空时向前删除字符簇或选文；空输入首次提示，800ms 内同键再按请求退出，其他按键或输入、焦点/场景变化或超时使确认失效；没有输入焦点时不误删别处或绕过草稿退出。弹层消费按键不穿透；Esc 优先关最上层弹层，无弹层且当前会话运行时请求中止，空闲不执行。Ctrl+O 切详情，Ctrl+L 重绘，均不改变工作、草稿或计量。显式退出入口保留草稿选择并等待清理，不把退出当持久化中止。
- **T7 终端边界。** 复用公开 pi-tui 组件、可靠的复制适配和屏幕保留退出接口，宿主输出有界退出摘要，不打印全部长历史。正常退出及可捕获故障恢复光标、raw mode、鼠标/粘贴模式和原缓冲区；SIGKILL/掉电不保证自行清理，须提供恢复方法。浏览器原型和合成 Terminal 探查不能代替 macOS Terminal 的 IME、格宽、键码、复制与进程清理验收。

### E — 运行证据、压缩、存储和长期保留（#5、ADR-0002）

- **E1 原文。** 默认完整保留实际取得的用户输入、有效指令、模型请求/响应、工具参数/输出、检查及相关附件，包括失败、取消和已收到的未完成内容；不因时间、显示窗口或模型上下文限制静默丢弃。记录采集的是接口消息还是 provider payload，保留每次请求的有序组成与变换身份；transcript 不冒充最终请求，未取得网络载荷不承诺逐字节记录。认证传输密钥不采入，也不要求取得不可见思维、未返回内容或所有未读取项目文件。
- **E2 有界与完整性。** 内存、显示及送模有界，长输出分块持久化、背压和引用分页。上游输出尾部及临时 spill 路径不足以作为长期档案；内容可靠保存后才提交其完整引用。区分完整取得、源未返回、采集缺口、显示截断、派生脱敏、归档、主动清理、损坏和暂时不可读。固定证据保护实际内容及必要依赖，已缺失内容不能显示固定成功。
- **E3 身份和事实。** 关联项目/工作区、session/conversation、已受理任务、产品 run、durable task、逻辑工具调用、实际 attempt、执行版本/初态、检查与产物、证据、用户决定、后续判断、eval 和 improve。受理不等于启动；恢复关联原 run，真实重试另记 attempt。时间戳、路径、显示号或 provider tool-call ID 不单独充当全局身份。记录 Git/dirty 相关输入中实际取得部分，缺内容明确不可复现。事实、用户选择、规则分类及后续判断分别追加，保留修订关系和原结果。
- **E4 存储默认值。** 应用数据根位于业务项目外，可配置；每个 session 使用上游 durable SQLite，宿主元数据 SQLite 保存独有身份/决定/关系及可重建索引，大原文使用持久附件。上游权威状态与宿主独有事实不当作缓存删除，不改 durable 私有 schema。授权、请求和意图先可靠保存再执行；两个库与外部副作用不承诺原子事务或 exactly-once，启动核对跨库间隙，未知提交不盲目重发。限定原文文件为当前用户读取，不称作沙箱或加密保险库。
- **E5 故障。** 原文或恢复/授权必需记录无法保存时，停止放行新模型/工具并受控停止在途工作，保留已有内容与能保存的缺口，恢复后核对副作用；不为补日志重做操作，也不承诺磁盘满时仍能写成功错误标记。仅派生 span/可重建索引故障且必需数据可靠时，可标记观测降级；有界遥测队列不得无限积压、改变业务结果或触发工具重跑。
- **E6 用量和 trace。** 以 durable 已提交 `pi.usage` 的稳定来源去重投影，不逐 run 重加整个 session 累计量，不用差值伪装精确归属；无法归属留在可证明范围的未归属项。只在实际请求边界采集一次，避免 `completeSimple`/`streamSimple` 双计或重复消费流；span 持续至真实完成/失败/取消。真实重试、compaction、失败请求及工具费用按可观测事实记录，不臆造 SDK 内部 attempts，不重复加 reasoning 等总量子集。原始 usage 与带来源、币种、时间和版本的费用估算分开，重估追加，不冒充账单。coding/eval/improve/独立维护分账再给去重总额，unknown 不记零。
- **E7 自动与主动上下文压缩。** 两者只生成用于后续模型请求的摘要，原文保留，记录 automatic/manual、源上下文边界、摘要、接入状态、版本、请求身份、用量与来源。主动入口默认 `/compact` 及可见操作，headless 同义；空闲直接请求，忙时先持久化管理请求并在当前工作正常结束后执行。同会话同一未完成请求合并；排序只约束后续独立任务/管理请求，当前 run 的 steer 仍在工具轮次接入，不等压缩。只读历史不调用 compact；执行时重新固定源上下文。
- **E8 压缩生效与取消。** 摘要生成和 submission 已接入分别显示，过期/不完整摘要不接入；自动和手动的待接入 summary 均在整个 Harness 的核对/冻结范围。取消只处理对应队列请求、compaction task 或未接入 submission，与接入竞争以提交事实为准，不中止无关工作、不承诺撤销已生效摘要。noop/重复请求尽量在调用前识别，已发生调用仍计量；失败/中断保留原文、已有摘要和用量。自动成本归触发工作，空闲手动压缩为独立维护，不算下一任务费用或 coding 成功样本；上下文 token 变少不等于磁盘释放。
- **E9 归档、清理、迁移。** 无默认过期或容量淘汰。用户主动无损归档先校验还原可读性/hash，再处置原件；不压缩在写数据。摘要替换并删除原文属于有损清理，必须明确说明信息损失；所有清理都先预览实际范围、估计字节、受保护依赖及失效引用，用户明确提交后才执行。恢复、未完成/冻结请求、待决定、待接入摘要和固定证据依赖受保护。首版以依赖闭合的完整 session/归档单元及独立附件清理，检查共享库中全部分支，不修改上游私有 schema 逐条删消息。中断保留部分完成和最小删除记录，引用标已清理；保留的旧判断不因后来删除证据而改写。备份/迁移用包括 WAL 的一致性快照、验证可读、按各自公开机制升级；失败保留原件，未知格式不猜测。
- **E10 查询与外发。** TUI/headless 共享分页查询：项目、时间、kind、任务类型、状态/原因、执行版本、provider/model、完整性；先摘要再按稳定 ID 取原文与关联。报告筛选范围、更新位置、样本/缺失，索引陈旧不写成“没有发生”，查询/导出不触发模型、恢复或计量。improve 显式调用允许声明范围内的脱敏摘要与少量必要片段发给配置模型，不逐片段再问；扩大项目/范围/外发目的另行明确。本地保真原文和脱敏派生视图分开，不能声称原文全部脱敏或能识别所有秘密；不能安全提供的片段遮蔽并说明。历史指令样文本只是数据。其他导出显式选择范围和目的地，外部 tracing 默认关闭。

### V — 手动 eval 与改善判定（#6、ADR-0003）

- **V1 最小 eval。** 一个手动入口、顺序 runner、少量固定 TypeScript/Node 案例与本地可读/机器可读报告，共用 runtime 和现有证据。四类任务为局部修复、多文件小改动、已修复问题回归、不应改动的反例，可共用 fixture，无测试数量配额，也不限制产品只能处理 Node 项目。每例固定输入、可取得初态、可改范围及真实验收规则；历史聊天或 hash 不替代 fixture。公开回归集可参与开发，暴露过的案例不继续称未见独立集。
- **V2 计划。** 批次执行前固定目的、baseline/candidate 内容、一个主目标、保护行为、目标案例与仅保护案例、fixture/lock/dirty 输入、grader/门槛内容及身份、两侧版本/环境/缓存/模型配置、所有 case×版本×重复的身份/配对/次序、重试限额、超时、调用/用量限额和费用口径。每批展示这些范围；完整 eval 命令或 improve 选择已包含授权则不重复确认。缺有效限制不启动付费批次；无判定门槛可诊断但不能正式判改善。扩大范围或预算需新决定。
- **V3 独立试次。** 两侧同初态和预算、不同 session/空间，按预先记录的顺序交替先后；每 trial 新建环境，不带入上次答案、文件或进程。独立 HOME、临时区及可写缓存，只复用经校验的只读依赖。准备、任务、评分时间分别记录，用户等待不算模型活跃。固定 seed 不保证服务端确定性。重新评分追加判断而不改 outcome；实际补跑新建 trial 并关联首败。
- **V4 正式隔离。** 选一种现成隔离能力并验证，不自研通用沙箱/多后端。可信外层 runner 持有原 fixture、计划、grader、隐藏预期和报告；被测 runtime、工具、依赖与产物全部在受限侧，修改 runtime 也不能控制可信评分。限制宿主 HOME/凭据、其他 trial、共享可写 Git、历史答案、控制 socket/进程通道与任意网络；模型调用由可信宿主按预算中介，密钥不交被测代码。依赖预备，额外网络入计划。worktree/session 分离、prompt、环境清理或 hash 检查均不足以证明隔离；未落实边界的本机试跑只标诊断，不能暴露隐藏资产或声称正式改善。
- **V5 产物和评分。** 评分前确认执行及子进程结束、固定最终产物；只导出声明范围普通文件，不跟随外部链接、不执行导出内容。需运行产物时在同样受限的评分执行区，隐藏预期留在可信侧比较，不以候选修改的测试或“通过”日志为准。实际越界、污染或无法确认边界有效使相关 trial 无效并停止受影响后续工作。grader 故障是无法评分，不自动把候选判 FAIL；可靠必要要求失败可判 FAIL，不必等全部检查。
- **V6 预算与失败。** 默认不自动重开失败 trial；请求重试受计划限量并计入原 trial。开始新 trial/请求/重试/compaction 前检查额度和时限，重启不重置预算或截止点；计入两侧、失败/重试、压缩和评分成本。未知用量只有在可证明在途上界仍约束预算时才继续，否则暂停新请求。取消不证明退款或账单停止，残留进程未确认结束不复用空间或开受影响试次。失败、超时、取消、需求变更、预算停止、服务故障、grader 故障、无效和未运行分别留在全部计划中，保留首败；不能重跑到成功再覆盖。
- **V7 验证按影响选择。** 无行为文案/精确去重做一致性和加载检查；确定性 bug 做实际回归；启动、内存、体积、查询问题做相应基准；模型策略/prompt/skill 的行为或成本/延迟变化才做 fresh 对照。复用适用的既有检查，不强制每次全量 eval、第二 reviewer 或新测试框架。判定时间/调用/用量须由可信 runner/provider 边界或独立观测提供，候选 runtime 自报只能辅助。
- **V8 效果规则。** 任务达标与效果分开，先正确性/授权等硬约束，再保护项与主目标，不能用综合分抵消错误。随机行为按预定计划重复，无次数/阈值依据可先诊断，不能看完结果改门槛。逐主目标案例、逐配对定义差值 d（正为更好）及预定最小收益 δ>0；软保护项另定容忍度，硬约束零退化容忍。改善要求全部计划完成且有效、候选及保护项达标、每个主目标配对 d≥δ；成本/延迟改善还要求两侧任务效果达标且完整可比。无明显差异要求全部计划完成且有效、硬约束与保护项通过，并且每个主目标配对 −δ<d<δ。有效证据证明新增硬回归即可判退化并停止；软退化要求完成有效比较，主目标每对 d≤−δ 或对应保护项重复一致越过容忍度。其余为证据不足，包括未完成、污染、缺口、单次随机成功、无阈值或方向不一致。先判已证实退化，再改善/无明显差异；已发现硬失败始终保留，无法归因新增则报告不达标及效果证据不足。
- **V9 报告与规则修订。** 全部计划 trial、执行状态、outcome/评分/版本/初态/隔离证据与原因可追查，两侧列计划/启动/正常完成/可评分/通过数和有效配对。通过率=通过/可评分，完成率=正常完成/计划，覆盖率=可评分/计划，零分母 N/A；可评分可包含明确 FAIL 的错误/超时，不是正常完成的子集。显示总耗时/费用、缺失与配对差异，不只挑成功。grader 独立版本化，可对相同两侧产物重评分；改变初态、任务或行为须新试验，不能同时改候选与 grader 来证明原候选有效。内容和必要证据固定保留，结论仅限本批案例/环境，不外推普通全权限执行或总体稳定性。

### I — improve 的建议、选择、执行与生效（#7）

- **I1 触发和受限分析。** 一个内置 improve、一条显式入口，普通 coding 不自动跑 critic。忙时独立排队，绑定原会话/项目，开始时固定取证截止点，不随 UI 切换目标。只开放范围内摘要、脱敏证据及相关源码/配置视图，不给任意 write/edit/shell；报告由宿主保存。分析须有可执行的时间、请求/用量限制，缺失先补齐，耗尽保留不完整报告，不自动加预算。先当前任务/会话，按需同项目近期同类摘要再必要片段，默认最多 5 候选、无最低数量，零候选合法。
- **I2 候选合同。** 每项有稳定 ID/revision（显示号仅报告内有效）、问题/目标/适用版本、可追查事实和必要成功反例、证据覆盖/缺失及分开的原因假设、最小动作/可改范围、验证/预算/保护项、风险/回退、是否写回或启用及条件/时机、依赖/冲突。检查当前机制和历史决定，不因缺某 skill/CI 自动建议安装，不虚构收益；缺目标或验证条件可提补充验证候选，不能用“全部优化”代替范围。建议阶段无需完整 patch，候选文本本身不授权。
- **I3 可改对象。** 明确的项目文件、agent 配置、prompt/skill、pi-durio tools/runtime 源码以及独立 eval 资产均可成候选。自身源码必须由用户显式登记并核对实际内容/build 与目标对应，名称或 remote 相同不足以证明；缺少条件保留建议，不寻找同名目录或改安装包。凭据不作为候选材料。eval/grader 变更独立处理；Markdown 行为改动不因后缀而降为纯文案。
- **I4 结构化选择。** TUI 逐项选“执行声明范围”“仅验证”“暂缓”“不再建议”，默认不选，汇总目标、依赖、冲突、顺序、验证及总预算后一次明确提交。headless 用等价结构化决定；自由文本只补充意见，不推断执行同意。选择绑定报告/候选 revision、目标/基线、模式和声明步骤；刷新或实质漂移使旧选择失效。先可靠保存决定再动作，同一批次重复提交只读已有状态，不重复执行；未选项或依赖不自动执行。
- **I5 仅验证与准备。** 可在声明临时副本/可回退内容中构造候选和执行预算内检查，保存产物及证据，但不写回正式目标、切默认或因通过而启用；默认不含外部写操作。编辑即生效的配置/规则/skill 也先在临时目标准备，不能先覆盖再称未启用。临时目录不是权限沙箱；不强制所有项目有 Git。无法在选定范围安全验证/写回时保留候选和阻塞。
- **I6 抑制。** 暂缓不原样立即重提，只有条件/证据实质变化才说明原因再提；不再建议在明确项目或配置目标范围内持续抑制同一问题，直到用户主动恢复，换 ID/措辞、普通升级或新增同类记录不解除。不扩展为全局禁令，不删除历史失败/原文，不另建语义检索服务。
- **I7 顺序、组合与失败。** 一个提交批次和有序清单，复用写入者约束。无相互影响项可逐项执行，共同目标/行为影响的项作为组合验证，单项通过不代表组合通过，组合效果不分别归因。不兼容组合要求调整选择；范围内必要步骤连续完成，扩大动作/预算才重新决定。失败、取消、未知副作用、记录失败或基线失效时默认不启动剩余项；保留已完成/失败/未运行。独立完成项不自动回滚，未完成组合不正式写回/启用，已发生部分写入进入核对。仅因批次停止而未运行的独立项，前提/原授权/预算/版本有效时可显式继续，普通消息不解冻。
- **I8 验证和启用。** 写回前再次核对用户编辑、目标与基线；启用内容必须就是验证内容，验证 A 不能复制 B 后称通过。性能主目标必须证明预定收益才启用，检查通过但无明显差异/证据不足仍不启用，不自动加样本或事后改称“清理”。非性能候选按 V7 的影响范围选择直接检查、真实回归、基准或 fresh 对照，仍保留必要保护项；确定性修复与无行为变化清理不额外强制模型 A/B。配置/prompt/skill 可设后续新任务默认；tools/runtime 产出已验证可启动新 build，启用仅面向后续显式启动的新进程，当前进程不自替换、自重启。build 生成、默认设置、实际观察生效分别记录，旧 pending 不热迁移。
- **I9 回退与授权。** 候选先说明可行回退、保留旧内容，缺能力或不可逆副作用明确说明。显式回退前核对当前内容和后续用户编辑，不用 reset/clean 或整目录覆盖擦除他人工作；回退不逆转既有副作用。正式写回失败只有已声明补偿、目标精确对应本批产物且无未知外部副作用时，才在原授权内撤销本批写入。执行候选不隐含提交、推送、发布或数据清理，不允许被托付代码改宿主授权/预算/效果判断。
- **I10 结果。** 分开记录用户决定、执行状态、正式写回/默认/新工作或新进程生效/回退事实、效果结论及范围。记录实际 diff/配置/build、验证计划、首败与全部试次，重开报告只读不重复应用或计量。采纳、启用、检查通过均不等于改善；后续真实工作可提供新证据但相关性不证明因果。制作候选、分析、eval 和 coding 去重分账。

### M — 六项 LLMOps 指标与最少人工反馈（#9）

- **M0 共同统计合同。** 日常按受理时间在 `[from,to)` 的独立任务选样，累计这批任务截至 `as_of` 的状态/费用；排队、冻结、取消、未运行也保留。steer 不新增任务，follow-up 受理入样本、接入才有 run；重试不新增任务，合法恢复沿用身份，新独立工作另记并关联。eval 按固定计划及两侧分开，不与日常合算。显示项目/种类/任务类型/执行与规则版本、成员、时间窗、未知身份及筛除原因。事实发生时间与证据收到时间分开，新反馈/规则/报告追加修订；原始要求变化保留且注明不可比。零分母 N/A，不是 0%/100%；有分母但缺依据为 unknown/partial，不假装 N/A。历史趋势不授权动作或替代正式因果判断。
- **M1 任务验收。** 同批日常任务用 N=已受理、B=已启动、C=正常执行完成、G=有有效确定验收判断、S=通过；同时报告成功率 `S/G`、完成率 `C/N`、验证覆盖 `G/N` 和计数，可另列 `S/N` 但明确名称。G 不必属于 C，错误/超时有充分固定证据可判 FAIL，正常结束也可无法评分。PASS 须覆盖必要要求，一项可靠必要失败足以 FAIL；grader 故障/污染/不足不伪造 FAIL。每最终结果按截止点用有效修订，不挑最有利；矛盾判断中可靠失败仍计 FAIL，证据有效性不明则无法评分，原失败事实仍展示。
- **M2 成本。** 每成功任务成本=`同一受理样本全部任务关联成本/S`，包括失败、取消、重试和触发的自动压缩，不能仅算成功项费用。样本累计与期间实际发生的全种类开销是不同视图，不混分子分母；在途样本暂计。coding/eval（含两侧及准备/执行/评分）/improve/独立维护分账后去重汇总，不把 eval 的 run 再记一份 coding。共同/未归属开销只计可证明的总范围，不猜给任务；可能属于样本的未归属费用、缺 usage/价或在途使完整值 unknown/partial。可列已知部分/S，但不冒充完整值、最终值或无证明的下界。S=0 时 N/A，仍显示开销/缺失；跨币种分别报告，换算注明来源/时间。费用是带版本的估算，不含未记人力/折旧，非账单实付。
- **M3 双时钟。** 执行历时=真正终止−受理，包含队列、重试、用户等待和跨重启停顿；验收历时=对最终结果/要求/规则作出的首个仍有效确定判断−受理，PASS/FAIL 分组，不延长到“终于通过”。撤销/无效判断留旧时间但不占当前首个有效判断，尚无判断为待验收；后来返工不自动使旧验收失效。冻结/恢复核对不算终止，同一任务恢复继续时钟，跨版本新任务分身份。单调时间优先，跨进程墙钟注明可靠性，回拨/缺端点不造精确值；展示排队、用户等待、活跃、离线/恢复及未知分段，重叠子过程不直接相加。未结束者的截至当前等待不混入完成均值，均值/分位附有效/缺失数量。
- **M4 人工介入。** 仅为原要求达标而纠错、手工修复、接管/救场；正常授权、必要澄清、新需求和 improve 选择不算。观察阶段从开始至首次交付或终止，包含暂停/恢复。已启动且阶段结束 Ni=I（有介入）+Z（有覆盖全阶段无介入证据）+U（未知）；主报告 `I/Ni`、覆盖 `(I+Z)/Ni`、事件数，U>0 时完整率未知，可附逻辑范围 `[I/Ni,(I+U)/Ni]`，不是置信区间。未结束阳性另列；同任务多次介入只计一个受影响任务。日志完整、steer 数量、文件变化或无投诉不能证明无介入。
- **M5 回归与返工。** 受控回归按同一保护要求×案例×重复配对；P 为计划保护配对，V 为两侧有效且该项 baseline 通过的可比较配对，R 为 candidate 新失败，报告 `R/V` 和 `V/P`、全部数量/排除原因。baseline 整体失败但该保护项通过仍可形成新增回归，硬回归不能被低平均率抵消。日常返工另按首次实际交付选样，未验收交付也纳入；首次交付为宿主正常结束并交付结果/结论，非中途自报、临时 patch 或失败诊断。默认观察 `[首次交付,首次交付+7×24h)`，返修不重置窗口；原要求未满足的已提出/开始纠正算阳性，未核实投诉不算，新需求及首次交付前修复另列。截至 as_of 满 7 天的成熟交付为 Nr，其中 Rr 为窗口内明确返工、Zr 为有覆盖全窗无返工证据、Ur 为其余未知，Nr=Rr+Zr+Ur。报告 `Rr/Nr`、覆盖 `(Rr+Zr)/Nr`；Ur>0 时完整返工率 unknown，可附逻辑范围 `[Rr/Nr,(Rr+Ur)/Nr]`；未成熟阳性单列，满 7 天无反馈仍 unknown。迟报按明确发生时间修订，时间不明保留归属未知，窗口外事实另列。原交付、反馈、返修/人工改动及结果关联，不能无反事实证据归因模型。
- **M6 故障。** 任务分母为 B=已启动；F=至少一次已观察运行故障，恢复不抹除，Zf=已终止且完整观测无故障，Uf=其余无已知故障，B=F+Zf+Uf。报告 `F/B`、因故障终止比例、恢复/未处置事件、覆盖 `(F+Zf)/B`；Uf>0 则完整率未知，可附 `[F/B,(F+Uf)/B]`。入队异常另列。模型/工具分别按可观察实际已发起 attempts 计算错误比例，另列正常返回、已确认正常取消/计划停止、未结束、未知及覆盖。业务检查失败、预期无匹配、正常取消、预算停止、必要授权不自动算运行故障；非零退出不一概为工具异常，取消前故障保留，停止失败可成故障。SDK 不可见重试不猜数量，恢复已提交结果不新增 attempt。grader、派生观测和执行故障分别报告；合成故障处理通过不抹去被测失败也不混进真实日常效果。
- **M7 反馈与报告。** 复用充分检查及正常交流中明确对象/含义/范围的人工判断，保留原消息/动作与规则来源；不要求重复填表、结束必评、强制弹窗、定时追问或额外日常模型分类。模糊反馈保留 unknown，不为报表打断用户；“通过”不证明无人救场或 7 天无返工。提供可选补记/纠正，小型本地查询生成一致的可读和机器可读报告，包含修订、范围、分子/分母/单位、数量、覆盖/缺失/未成熟、成本/时钟来源、事实与判断引用、可比限制。查看不调用模型、触发执行或重记费用。

### A — 首版完成与工程顺序（#8、#9）

- **A1 真实路径。** 首版技术验收必须有真实 DeepSeek coding/工具轮转、四类代表任务的实际产物/检查，以及真实 improve 分析生成候选→用户选择→必要验证→正式写回或适用新任务生效→重开记录的闭环。可用有已知可改问题的小 fixture，不要求发现新优化或获得性能收益；不能用预填候选替代真实分析。零候选合法但不能单独证明执行链。TUI/headless 接线和 Terminal 分别验证，不要求同案例每入口重复付费。
- **A2 轻量与接受。** 同口径报告自有维护代码（含统计边界）、生产安装/分发体积（Node/原生/开发依赖是否计入）、冷启动、空闲/代表性长会话 RSS、记录增长、写盘/查询、大输出及 coding/eval/improve/维护用量费用，附机器、Node/依赖、终端、负载、过程和重复数据。区分本地与网络/模型时间，无法分离说明；正常完整原文磁盘增长单列。必需本地数据未取得不能称报告完整，provider 未返回 usage 仍 unknown。技术验收和测量完成后由用户本机试用并明确日用接受；要求先修正则仍待接受，修复计划或反馈不等于接受。
- **A3 交付状态。** 设计可交接、技术验收完成、日用接受、首版完成、对外发布分别记录。首版完成要求全部必要技术证据与明确日用接受；任一硬约束失败不能用低成本抵消。真实凭据/预算/隔离/Terminal 证据缺失时保留未运行/受阻/证据不足，其余独立工作继续。发布需要独立授权及对应工件验证。
- **A4 实施顺序。** 先验证精确工件公开入口、完整原文接入、真正只读历史/恢复能力、一个现成 eval 隔离机制及真实 Terminal 输入；随后 runtime/headless 与基础证据同步形成，再接 TUI/查询/压缩/保留，完成手动 eval，接 improve 选择执行，最后真实整体验收、轻量测量和本机试用。指标随已有记录/查询接入，不另建平台。从首次持久运行就留身份、原文、授权和用量，不事后补造。
- **A5 工程阻塞。** 文件划分、命令拼写、报告字段、测试案例数量、页大小等可逆实现选择由实现者依据既有接口处理。实际付费批次次数/预算、负载和判定门槛在执行前固定。若只能维护 fork、更换核心依赖、放宽既定恢复/授权/隔离/保留保证或实质扩大平台/成本才能解决，保留失败证据和影响，停止受影响路径并重开相应决策，其余独立工作可继续。

每项证据关联要求、实际候选内容和执行条件、方式、结果及缺口；工件包含必要源码/分发物、lock、有效配置/指令、dirty 输入及 fixture/grader 内容，不能只存 hash 或临时链接。区分 PASS、FAIL、NOT RUN、BLOCKED、证据不足；验收证据的 N/A 只用于确实不在范围的分支，不用来隐藏未实现、无预算或无环境；指标零分母按 M0 显示 N/A。故障注入中“正确阻断”可使处理行为 PASS，被测任务仍保留失败/未知。

真实批次在执行前固定案例、要求、版本、次数、预算和可观察结果，保留全部计划项、首次失败和修复后的新关联记录；未跑或失败不能删除后宣称整批通过。首版不要求性能候选获胜，也不以单次随机成功证明稳定。必要的已有确定性检查在代码、输入、依赖和环境仍适用时复用，相关变更、新失败或未覆盖风险才重跑/扩测。实现建立的实际项目检查须完成；本规格不虚构尚不存在的测试命令或 CI。
