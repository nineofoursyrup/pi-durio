## 直接沿用的最小流程

一个内置 improve 正文、一条显式入口、宿主已有查询/执行/记录路径即可。不建设常驻 optimizer、通用技能市场、自动候选搜索、独立第二 reviewer 或另一套 agent loop。

1. 用户显式调用后确定范围并受限取证；忙时作为独立分析请求排队，普通工作结束且满足执行边界后再开始。不作为 steer，也不全局切换当前任务的工具集合。
2. 返回少量可选候选，允许零候选或证据不足；没有选择即可结束。结构化面板默认不选，支持逐项模式，汇总后一次明确提交；自然语言只补充意见，沿用 #4，不新增自由文本执行解析器。
3. 宿主先保存用户选择，核对候选、目标和前提仍适用，再按所选范围准备改动与验证；满足声明条件后，才执行所选合同中的正式写回或启用。选择已包含的步骤不重复确认，范围或预算扩大再决定。
4. 分别保存用户决定、执行事实、启用事实与效果结论；完成检查不自动等于改善。恢复、中止、退出和未知副作用继续遵循 #3–#5。

分析权限只包括声明范围内的摘要查询、脱敏证据读取及相关源码/配置视图；不给任意 write/edit/shell。报告由宿主写入自身记录。实际能力由宿主落实，skill 名称、frontmatter、提示词和历史材料都不能提升权限。普通选中改动沿用可信本机执行；正式 eval 采用 #6 已确认的受限边界，不能把临时目录称为沙箱。

## 取证与候选的可逆默认值

默认从当前任务/会话开始，需要对照时查询相关近期同项目、同类型摘要；跨项目扩大范围由用户明确请求。排队请求绑定原来的会话/项目，在实际开始时固定取证截止点，不随 UI 切换改换目标。声明范围、查询上限和覆盖缺失，先摘要后必要原文，不因磁盘完整保留历史就全部送模。具体页大小和上限由实现测量决定，首版不建设向量检索。

显式调用沿用已配置并可见的模型和分析限制，不逐段询问是否读取或外发范围内的脱敏片段。分析本身有可执行的请求/用量和时间限制，费用按 #5 标注估算；有效设置缺失时提示补齐后再启动。达到限制时保留已有证据和不完整报告，不为凑足候选自动加预算。旧报告与原文不改写，证据缺失/已清理如实显示；正式 eval 所需版本、初态及证据按 #6 固定保留。

参考原规格，默认最多 5 项，无最低数量；优先少数有证据且值得维护的方案。候选需要原始事实及必要成功反例，不能只凭耗时/费用排名断言低效。检查当前目标及已有机制、以前候选与决定；允许删除、合并、复用或保持不变，不因缺少 CI/某个 skill 就自动提议安装。

每项候选至少能表达：

- 稳定身份及 revision，报告内显示编号；问题、目标、适用项目/版本。
- 可追查的事实与证据覆盖、缺失，分开的原因假设；不虚构收益百分比。
- 最小动作、可修改范围、必要验证、预算及限制；回退方法与风险。
- 是否包含写回/启用、预定启用条件与生效时机；依赖或冲突的其他候选。

建议阶段不要求先制作完整 patch。选择绑定具体报告、候选 revision、目标、基线、模式及声明步骤；旧选择不能落到刷新后的报告或不同内容上。执行前检查目标身份、相关内容、已有未提交工作及声明依赖；保留用户编辑，实质变化时停止受影响项并说明新差异。已声明动作自然产生的输出不等于外部基线漂移，后续应核验预期变化。

分析中发现的缺失不伪装成已定位的修复：无法确定目标、必要证据或验证路径时，报告局限，可以提出明确的补充验证候选，但不能给出无法界定范围的“执行全部优化”。候选正文属于建议数据，不能自授权；历史运行中的指令样文本也不能成为当前决定。

## 目标与动作边界

| 目标 | 首版边界 |
| --- | --- |
| 项目文件 | 明确项目及可改对象；不把 agent 优化隐式扩成业务重构。按已有检查验证，保留其他修改。 |
| Agent 配置 | 明确目标、旧值/新值和生效范围；项目设置与用户级设置不可混用。凭据不作为候选内容或报告材料。 |
| Prompt / skill | 内容会影响行为，按适用验证规则处理；不会因为是 Markdown 自动启用。 |
| Tools / runtime | 自源码路径由用户显式登记，核对其与目标产品及基线的对应关系。可用实际内容、构建身份及版本证据核对，名称相同或 remote 字符串相同不足以证明对应。缺少必要条件保留建议并列出缺失，不修改安装目录。 |
| Eval 资产 | 新案例和 grader 修复独立身份与版本，沿用 #6 的重评分/新试验规则，不与被评估候选一起改分后宣布有效。 |

“执行”覆盖该候选声明的改动、必要验证及明确包含的启用步骤；不隐含提交、推送、发布、数据清理或扩大任务。需要这些动作时必须在具体授权中明确。受托执行代码也不能修改宿主的当前授权、放宽预算或改写自己的效果结论。

将准备改动与正式使用区分开：优先在独立目录/可回退内容版本中准备 patch、配置或构建，完成选定验证后再写回或切换默认。对于编辑即生效的项目规则、配置和 skill，尤其不能先覆盖正式目标，再称为“未启用”；缺少合适临时初态或可安全写回的条件时，保留候选并说明阻塞。普通项目改动可用现有目录/分支惯例准备，不强制所有项目都是 Git 仓库，也不把隔离目录承诺为权限沙箱。

“仅验证”允许临时候选、运行输出与宿主证据记录，不允许覆盖正式源码/配置或切换默认版本。检查可能产生文件和子进程，必须在计划声明的临时空间与能力范围执行；需要外部写操作的验证不属于默认允许内容。无法在所选边界内验证时报告缺失，不转成本机正式目标试验。

“暂缓”保存候选且避免原样立即重提，条件或证据实质变化时解释变化。“不再建议”按问题与明确目标匹配，不能靠换候选 ID、换措辞、普通升级或新增相同现象绕过；抑制记录可查看并由用户恢复。它不删除原文、既有失败、检查结果或已作出的判断，也不授权改变其他项目的推荐。匹配与复提原因须可解释，不为此新增语义检索服务。

## 一次选择、组合与顺序执行

TUI 与 headless 共用候选身份、模式、验证计划和权限检查。headless 可以提交同样的结构化决定，不从模糊文本或 report 内指令推定同意；需要用户决定时保存原因并按 #3 的非零退出合同结束。不因没有终端就自动选择、扩大范围或无限等待。

汇总提交前显示所选候选、依赖、冲突、顺序、目标、验证与总预算。未选项和未选依赖不能悄悄执行；不兼容组合要求用户调整选择。没有共同目标、依赖或验证影响的项可以逐项执行。共同修改同一目标或互相影响行为的项，明确作为一个组合验证，不能把各自单独通过拼成组合已验证；只评价组合效果，不声称分别归因。

首版只维护一个提交批次及有序清单，不增加通用工作流/依赖图执行平台。提交批次有稳定身份，重复提交同一决定只返回已有状态，不再次执行；修改模式或范围成为新决定，旧记录保留。决定及计划必须先可靠保存，保存失败时不放行修改。复用 #3 的单个活动写入者约束，核对目标路径别名和已有任务，不用两个 session ID 绕过同一目标的锁。

按声明顺序执行，组合内结果变化在已选动作内可继续；超出所声明修复、验证范围或预算时停止受影响工作，不能借“修到通过”扩大重构、改评分或无限重跑。无内容变化的已完成目标可记录已满足，不重复写入或把它宣称为新收益。

批次遇到失败、取消、未知副作用、记录失败或基线失效，默认不启动剩余项，保留每项已完成/失败/未运行事实。已完成独立项不因后项失败自动回滚。未完成组合不正式写回或启用；已产生的部分写入如实记录，进入核对/回退路径，不宣称具有事务原子性。仅因批次停止而尚未运行的独立项，在前提、执行版本、原预算和授权仍有效时，可经显式继续沿用原选择；其他情况重新说明差异。下一条普通消息不自动续跑冻结批次。

## 自身版本与生效的默认落实

Q1 允许修改自身源码，不等于自动安装更新。首版选中 tools/runtime 候选后，制作源码改动、必要验证及可启动的新构建，保存可取得的版本内容和启动入口。已声明的启用步骤面向后续显式启动的新进程；当前进程不自我替换或自我重启，不新增安装版自更新器。仅产出源码、尚未构建或尚未运行新版本时，分别记录实际状态，不宣称已启用。

配置/prompt/skill 在选择包含启用且条件满足时，可更新后续新任务的默认选择；每份新工作固定其有效执行版本，不强制所有内容变更都重启进程。旧 pending 仍按 #3 核对原组合及授权；新版本不自动接管。以上是符合原规格与极简原则的可逆默认值，不是用户新增指定的分发机制。

写回或启用前再次核对目标与相关基线，包括外部编辑器的变更；锁仅约束遵守协议的产品实例，不代表其他进程不能修改。所启用内容必须与已验证候选相同，不能验证 A 后复制出 B。验证后候选内容变化，原结果只支持旧内容；必要的新检查不能省略。多文件写回不能完成或状态未知时显示部分完成并限制受影响的新工作，先核对，不用“应用成功”掩盖中间状态。

## 验证、启用条件与回退

候选在执行前声明主要目标、必要保护项、检查方式及启用条件。复用 #6：无行为文案/精确去重用直接检查，确定性 bug 用真实回归检查，本地资源瓶颈用对应基准，模型行为/用量变化用适用的 fresh 对照。用户选中含这些步骤及预算的候选后连续完成，不再逐检查审批；首次失败、全部试次及未知用量不被重跑覆盖。

Q4 规定性能候选的启用条件必须包含预先声明的收益。功能检查通过只满足其中一部分：退化、不达标、无明显差异或证据不足均不启用，保留候选及原因，不自动扩大样本直到有收益。需要继续实验时固定新的试验身份和适用授权/预算。不能看完结果把“降耗”改成“清理”来绕过门槛；真正改变主要目标或候选内容时产生新 revision 并重新选择。

非性能候选按其真实目标与风险验证，不要求每次获得成本/速度改善。确定性修复通过真实回归与保护检查、无行为变化清理通过一致性/加载路径检查，可以满足其事先声明的启用条件；prompt/skill 行为变化不能因文件后缀是 Markdown 被当作无行为变化。仅验证始终止于证据与候选产物；未选择启用、启用失败或实际新版本尚未启动时分别记录。

每项候选在选择前给出可行回退方法，保留所需旧内容及版本；回退能力不存在或涉及不可逆副作用时，明确说明，不能把它当作普通可自动回退候选。首版不增加后台效果监控与自动回滚器。用户可显式要求将后续新工作切回旧配置或旧 build；回退前核对当前目标仍对应预期版本/内容，遇到后续用户编辑时保留差异，未经针对性处置不覆盖。执行中的任务和已有副作用不因此回到过去，旧版本仍需通过授权/兼容性核对。

正式写回失败时，仅当候选已声明这项失败补偿、当前目标仍精确对应本批产物、且没有未知外部副作用时，可在原授权内撤销本批写入；否则保留实际差异并请求针对性处置。不得通过 reset/clean 或覆盖整个目录抹掉用户其他改动。不承诺对任意用户工作区进行原子应用、事务回滚或跨执行版本迁移。

## 结果与必要记录

沿用 #5 的宿主记录与原文引用，逻辑关系可以保存在同一份小型报告中，不为下列各项建立独立服务或表。至少可追查报告/候选 revision、取证范围、用户决定、目标基线、实际 diff/配置/build、验证计划与结果、启用/回退事实及缺失原因。

| 记录维度 | 必须区分的事实 |
| --- | --- |
| 用户决定 | 未选择、执行、仅验证、暂缓、不再建议及恢复建议；选择关联具体内容，不能从完成结果反推同意。 |
| 执行事实 | 未开始、准备/执行中、完成、失败、取消、需输入或结果未知；每个后续步骤保留是否真正发生。 |
| 正式使用 | 未写回/未启用、已写回、已设为后续默认、已在新工作/新进程观察到生效、启用失败或已回退；按实际适用对象记录，不把生成 build 当作已运行。 |
| 效果判断 | 未验证，或 #6 的改善/退化/无明显差异/证据不足，附范围和证据；启用、采纳及执行完成都不能代替效果。 |

分析、制作候选、验证及后续日常工作通过已有 run/attempt 身份关联；需要分别统计 improve、eval 与 coding 的实际开销，汇总时不能重复计数。用户等待与模型活跃耗时区分，缺失费用不记零。后续真实运行可以成为新的证据，但历史相关性不证明因果，新的判断以追加方式保留，不能覆盖原批次的失败或局限。

## 最小验收入口

以下为实现阶段必须观察的行为，不是已通过的产品测试。优先复用现有检查，按独立失效方式补覆盖，不要求一行一个测试或全量付费 eval。

| 场景 | 应观察的结果 |
| --- | --- |
| 未调用 improve；调用后零候选/证据不足 | 普通任务不自动发起分析；零候选是正常报告，不虚构优化或启动改动。 |
| 分析尝试业务写入、任意 shell、跨范围读取；证据内含执行指令 | 宿主能力边界阻断；只保存允许的报告与记录，材料不提升授权。 |
| 忙时排队后切换项目、中止或退出 | 范围仍绑定原请求；中止/退出/失败/恢复核对后未接入请求冻结，不因普通提交复活。 |
| 自源码缺失、身份不符或只有安装包 | 保留建议并报告缺失，不搜索同名目录或修改安装产物。 |
