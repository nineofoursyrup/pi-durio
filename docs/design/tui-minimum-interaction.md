## 设计问题与原型

原型要回答：在单列全屏界面中，用户能否区分补充与排队、中止与退出、历史查看与恢复，以及候选选择与实际效果？

采用 [单文件交互原型](../prototypes/tui-minimum-interaction-prototype.html) 展示这些流程；所有任务、输出、用量和结果均为模拟，状态仅为界面夹具。原型不连接 durable、模型、工作区工具或数据库，不是产品 runtime 的替代实现。双击 HTML 即可打开。

用户已选择界面形态，因此使用行为 walkthrough 验证语义，不再制作三套相互矛盾的主布局。浏览器原型可以检查信息层次、按钮效果、滚动和选择；它不能证明 macOS Terminal 的 IME、字符格宽、按键编码、PTY 信号或退出清理已通过。

另已针对精确 npm `pi-tui@1.1.0` 做[隔离能力探查](../prototypes/pi-tui-1.1.0-probe/README.md)：一次无模型合成 Terminal smoke 的 18 个观察通过，覆盖公开布局、输入、鼠标、宽字符与缓冲区退出接口。它不是 macOS Terminal.app 实测，不能作为产品通过的依据。发布制品与研究快照的光标实现存在差异；不改变 #3 的候选基线，实际 IME/光标行为仍待终端验收。

实施起点是复用公开组件及 `stop({preserveScreen:true})`，退出后由宿主输出有界摘要，避免默认退出打印完整长历史；macOS Terminal 复制需可靠的 `copySelection` 适配。宿主负责历史窗口、输出分页和保留上限，不能把 `ScrollView` 当现成的无界历史解决方案。

## 拟定的显示与导航默认值

- 常驻：工作区和当前会话标识、会话内容、输入、当前状态、模型、必要快捷键。已知用量简洁显示，未知或不完整明确标记；费用估算不写成实际账单。
- 状态说明当前正在做什么或为什么等待，至少分清运行、等待输入、重试、恢复核对、中止中、退出中、已中止与完成；是否已完成来自 runtime 已提交状态。UI 的滚动位置、展开状态和焦点不构成新的执行生命周期。
- 工具默认显示名称、简短参数、执行状态和有限输出摘要；失败和截断标记在折叠时仍可见。按需展开输出、diff、用量、trace、compaction 或任务详情。
- 长历史按窗口读取和渲染。展开大输出不一次性装入全部内容；区分“当前显示有限”“保留的原始输出本身不完整”和“原始内容已不可取得”。
- 用户上滚或展开阅读时暂停自动跟随，用可见的“回到底部”恢复。新输出不抢输入焦点、不覆盖草稿或重置手动展开态。
- 会话列表按需打开；查看历史只读，不自动续跑、调用模型或重做工具。运行中查看其他历史时，运行状态仍明确指向原会话；历史视图禁止提交，先返回活动会话再输入。中止操作必须写明目标会话，不能对正在查看的历史或后台工作静默猜测目标；切换执行工作区仍走 #3 的所有权检查。
- 小窗口先压缩次要状态字段并换行，保持输入和必要操作可达；再小则显示窗口过小的提示。最小列数与行数在实际终端验证时确定，不把浏览器像素宽度当终端字符格。
- 提供 `/help` 与命令补全；会话、恢复、队列、用量/trace 和 improve 从命令或可见选择入口到达。具体命令拼写是可逆默认值，不扩展为完整运维面板。

## 输入、中止与退出：按 Claude Code 习惯修订

2026-10-09 读取 Claude Code 官方 [Interactive mode](https://code.claude.com/docs/en/interactive-mode#general-controls)、[Keybindings](https://code.claude.com/docs/en/keybindings) 和 [Terminal configuration](https://code.claude.com/docs/en/terminal-config#enter-multiline-prompts)。这是当日公开文档参照，不是用户本机 Claude Code 的版本或自定义键位检查，也不更改用户的 Terminal 设置。

官方普通消息在忙时可于工具完成后接入，这与 Q2 的 steer 方向一致；其 Esc 中断后发送原队列的行为不沿用，pi-durio 仍执行 #3 的持久化中止和冻结未接入消息合同。参考键位不扩展为后台运行、回退代码、权限模式切换或热切执行版本等新产品承诺。

| 操作 | 拟定行为 |
| --- | --- |
| 空闲时 Enter | 提交新的普通请求。输入法组合尚未提交、候选菜单正在选择时，不误发任务。 |
| 运行时 Enter | 默认提交 steer；输入区常驻提示“补充当前任务”。“排到下一任务”显式提交 follow-up，不把普通文本猜测为两种不同动作。 |
| 多行输入 | Shift+Enter / Ctrl+J 换行，并提供反斜杠后按 Enter 的回退入口（去掉作为换行转义的反斜杠）。Option+Enter 可在用户自行配置 Option as Meta 时使用。Claude Code 官方称 Apple Terminal 支持 Shift+Enter，不等于 pi-tui 已验证该编码；真实 Terminal 验收必须覆盖，不能静默变成提交。 |
| Ctrl+X 后按 Enter | 显式提交 follow-up，与“排到下一任务”按钮同义；忙时等待当前工作完成。借用 Claude Code 的排队入口键位，不引入强制即时发送。普通 Enter 仍为 Q2 的 steer。 |
| 排队消息 | 显示内容、归属及待接入/已接入状态。待接入可撤回；撤回成功后才显示已撤回。与接入发生竞争时按 runtime 事实显示，已接入不能伪装成撤回成功。 |
| Ctrl+C | 运行中请求中止，先显示“中止中”；收到事实后才显示已中止或仍有结果未知。空闲时第一次清输入并显示再次退出的提示，保存可恢复的草稿；未编辑、未切换上下文时再按同键请求退出。正在停止/退出时不把连按当退出同意；运行中中止不算作空闲退出的第一次按键。 |
| Ctrl+D | 输入框非空且取得焦点时，删除光标后一个字符簇或所选文本，不退出；没有输入焦点时不误删别处或绕过草稿。空输入第一次提示，800ms 内再次按同键才请求退出；其他按键、输入、焦点/场景变化或超时使确认失效。弹层内不穿透触发外层退出。 |
| `/exit` / 可见退出入口 | 显式请求退出，有草稿时显示保留草稿的退出选择。先显示“退出中”，等待受管执行清理及存储关闭；保留可恢复工作，不等于持久化中止，不承诺退出后后台运行。 |
| Esc | 最上层菜单/弹层优先关闭且消费本次按键，不继续中止底层任务；无弹层且当前会话运行时，请求中止。空闲时不发起执行或退出。关闭恢复决策面板仍保留未知和限制；双 Esc 不引入回退/重做行为。 |
| Ctrl+O / Ctrl+L | 分别切换会话/工具详情与重绘当前显示；不更改工作状态、草稿、记录或用量。菜单及候选列表保留 Tab/方向键导航、Enter 选择；不因按键组合引入新的权限模式。 |
| 请求中止、退出、失败或进入恢复核对 | 未接入的 steer / follow-up 保留且冻结，不能在下一条普通输入时突然执行。“保留”只是保存文本；须显式选择重新接入且恢复条件满足后才解除冻结。已中止任务不因此变成普通 pending；新任务采用旧文本需明确重新提交。也可撤回积压项；持久化字段与恢复读取由 #5 衔接。 |
| 运行中 `/improve` | 单独标记为排队的改进分析请求，在普通工作结束并满足执行边界后进入受限分析。不作为普通 steer 送入模型，也不全局替换运行中任务的工具集合。 |

上游默认会保留失败后的 inbox，并可能在下一次提交时接入；因此冻结队列是宿主必须落实的执行约束，不能只是 TUI 灰掉按钮。没有实现证据前不宣称该行为已经具备。

## 恢复核对的展示

打开未完成会话先展示历史、最后已知状态与恢复条件，不自动启动调度。一个恢复面板至少展示：相关工作、最后确认到哪一步、未知内容、现有证据，以及每个可选动作的影响。

- 可靠证据确认已完成：保留原来的中断/未知记录，另显示核对结论；恢复后避免重做。
- 可靠证据确认未发生或适用幂等重试：展示证据及适用条件，沿用仍有效的授权才继续。
- 证据不足：提供针对具体未知工作的处置，不使用无上下文的通用“继续”按钮。需要重试时写明可能重复的影响；用户决定不改写未知历史。
- 结束旧工作：不回滚已发生的修改，不等于确认外部副作用没有发生；新任务不隐式接手旧队列。
- 执行版本不兼容或授权失效：只读查看原因与可行后续，不能用确认弹框覆盖 #3 的恢复前检查。
- Esc 或关掉面板：返回查看，未知与执行限制仍在。

确认卡只用于已有合同要求的用户决定。普通授权范围内的修改与检查不增加逐命令批准流程。

## improve 展示与选择

沿用原规格第 12–14 章及 GLOSSARY 中的 improve 定义。本票只确认用户看见什么、怎样选择；最终目标权限、动作合同和生效规则由 #7 确定。

Q5 已确认结构化面板为首版正式选择入口，汇总后一次提交；自然语言用于补充意见，不在本票增加自由文本直接执行解析器。

- 报告头显示范围、证据覆盖和缺失，允许零候选。候选显示编号与版本、问题、事实/假设、目标、动作、验证、生效范围和风险；详细证据按需展开。
- 默认不选中执行项。“执行已声明范围”“仅验证”“暂缓”等按项明确选择。仅验证与启用不能用一个含糊的“应用”按钮代替。
- 提交前在同一面板汇总候选、模式与影响；一次明确提交完成本轮选择，不在提交后重复询问已声明的步骤。
- 报告、候选 revision 或目标基线变化时，旧勾选不能落到新内容上；明确标记失效并重新审阅。显示编号 R1 不是跨报告身份。
- 提交后分别呈现用户决定、执行结果、效果结论；检查通过仍可显示“效果未验证”。
- “不再建议”的作用域、目标启用等语义沿用 #7 的最终合同，本票不通过界面文案预先扩大授权。

## 待验证场景与证据边界

| 场景 | 需观察的行为 | 原型能覆盖的部分 |
| --- | --- | --- |
| 工具运行时补充/排队 | steer 接入当前工作；follow-up 等当前工作完成；状态可见 | 模拟路径与文案，不证明 durable 接线 |

| 中文、emoji、长路径、长输出 | 内容可读、截断可辨、小窗口操作可达 | 浏览器视觉检查；终端格宽与 IME 待验 |

## 原型检查记录

2026-10-09 第一版浏览器演练如下；与 Q4 冲突的旧键位观察仅是历史，不作为修订后合同通过的证据。[当时原型和截图](../prototypes/archive/before-claude-code-keybindings/tui-minimum-interaction-prototype.html)保留，其他未变路径的有效观察可复用。

- 工具轮次结束后，steer 已接入而 follow-up 仍排队；当前任务完成后 follow-up 才开始。
- 请求中止先显示中止中，再模拟确认已中止；冻结文本转为草稿后尝试继续，仍拒绝重启已中止的旧工作。
- 第一版非空草稿下 Ctrl+D 展示退出选择，Esc 返回不丢失草稿；明确退出、模拟关闭后重新打开，仅查看且保留草稿。Q4 修订后，非空 Ctrl+D 改为向前删除，此项的键位部分不再适用；显式 `/exit` 仍使用保留草稿的退出选择。
- 关闭恢复核对面板后继续仍被挡住；可靠证据确认后显示不重做；执行版本不兼容时仍限于查看。
- improve 报告更新清除旧选择；重新选择 R1 仅验证、R2 暂缓后，一次提交分别显示验证完成但未修改目标、未执行，以及效果未验证。
- 窄列长输出未产生横向溢出；离开底部后追加输出保持 scrollTop 为 0，显示记录不完整与展示截断的区别。此处是浏览器尺寸观察，不是终端格宽或内存基准。
- 修正演练导航：在弹框内或通过快捷键执行与当前步骤等价的动作，也会推进引导，避免被弹层挡住下一步。

Q4 修订后的补充检查（2026-10-09）：

- 浏览器键盘：Esc 先关闭会话菜单且任务仍运行，再按才进入中止中并冻结未接入队列。Ctrl+D 在 `A👩‍💻中B` 的 emoji 前删除完整字符簇，保留 `A中B`；空输入快速连续两次进入退出中，超过 800ms 或插入其他按键后只重新提示。
- 浏览器键盘：Shift+Enter、Ctrl+J 和反斜杠后 Enter 均只产生换行；Ctrl+Enter 不提交请求。
- 模拟按钮：空闲 Ctrl+C 清空并暂存草稿，草稿可恢复；编辑后再按只重新清空，未编辑再次按才进入退出中。此处验证状态语义，没有声称验证真实 Ctrl+C 键盘路径。
- 浏览器限制：最初 `Ctrl+X → Enter` 观察到 steer。拆开检查后，Ctrl+X 本身未出现组合提示，Ctrl+C 同样未触发页面变化；原生按键入口也未使 Ctrl+X 到达页面。原型状态检查收到 `followChord` 后会生成 follow-up，但浏览器端 Ctrl+C / Ctrl+X 按键交付仍未验证，疑似被内置浏览器外层拦截。保留这一失败观察，不把按钮或状态检查算作键盘通过。
