## 最小形态与用例

首版只有一个手动入口、一个顺序 runner、少量固定案例和一份可读/机器可读报告。`eval plan`、`eval run`、`eval report` 仅为建议命令拼写；可以由一个命令的参数承担，不要求三个模块。计划与报告可保存为本地 JSON，引用 #5 已有原文和运行记录，不复制一套 trace、usage 或数据库；case/trial/grader/outcome 是逻辑边界，不要求四张表或四个类。

不增加后台调度、自动搜索候选、日常 LLM critic、排行榜、Web 面板、插件式 grader 系统或多种隔离后端。首版可执行检查优先；主观输出必要时由明确 rubric 和人工反馈解释，不以 LLM judge 作为必需依赖。人工判断不伪装成自动检查。

首批覆盖下面四类模型任务即可，可以共用一个小型 fixture；用例数由独立失效方式决定，不设置数量配额。每个案例须固定验收要求、可修改范围和真实可执行检查，不能只看模型回复或 patch 大小。

| 代表任务 | 检验的实际行为 |
| --- | --- |
| 局部修复 | 重现一个明确错误，修复目标，相关既有行为仍正确。 |
| 多文件改动 | 完成跨文件的一项小需求，接线及必要调用方一致，检查真实运行路径。 |
| 已修复问题的回归 | 旧问题不复现，也没有破坏相邻行为；保留正例和边界输入。 |
| 不应触发的反例 | 输入相似但不适用规则，或只要求分析；不产生未经请求的改动。 |

恢复/副作用、授权与选择、usage 去重/unknown、原文留存及隔离边界沿用 #3–#5 的确定性验证义务，不为它们都支付真实模型调用。#7 再给出 improve 特有案例（如零候选、仅验证、选择失效）；#6 提供验证规则，不提前决定 #7 的操作权限。

首批案例由实现阶段建立；从真实历史提取案例时必须补齐可取得的初态、任务输入和验收要求，并去除实际凭据与外部副作用。已有聊天或 hash 不能替代 fixture。报告列出已覆盖的四类任务、尚未建立的案例和未覆盖语言；缺案例不算通过。固定回归集可公开并参与开发，不能宣称它是未见测试集；用新案例作独立检验时，记录其是否已被用于提出/选择候选，暴露后不继续称为独立。

## 计划与最小证据

一个案例对应固定输入、初态、达标规则及其版本；一个 trial 对应一个案例在一个执行版本下的一次尝试，并关联 #5 的产品 run 和真实模型/工具 attempts。outcome 保存实际产物、终止事实与检查证据，grader 据此追加判断。重新评分不改写 outcome；用户选择、执行结束、通过检查与改善分别记录。术语见 [GLOSSARY](../../GLOSSARY.md)。

执行前固定一个批次计划，至少包含：

- 目的与变更：直接检查、专项基准或 fresh 对照；候选相对 baseline 的内容差异、假设、一个主要目标指标和必须保护的行为。预先区分衡量主目标的案例与仅作回归保护的案例，不能看结果后改分组；多个改动一起试验只能评价组合，不能分别归因。
- 案例与初态：每个案例的输入、fixture/依赖 lock、允许变动内容、grader/规则/门槛的可取得内容与身份。含 dirty 文件时保存必要 diff 和未跟踪输入；缺内容则预检失败。
- 执行条件：两侧 build、工具、有效指令、模型请求配置与可取得的返回身份，隔离配置、环境和缓存口径。模型别名不是不可变权重版本证明。
- 试次清单：全部 case × 版本 × 重复的稳定身份、配对关系和执行次序，连同尚未运行项一起保存；允许固定种子，但不把 seed 当成服务端确定性的保证。
- 限制与判定：重复次数、重试上限、单 trial/整批时间、调用/用量限额、费用估算口径、目标变化阈值及保护项容忍度。没有有效限制不得启动付费批次；没有判定门槛仍可诊断，但不能输出正式改善结论。

顺序执行，同一案例的 baseline/candidate 使用相同初态与预算、不同 session/目录；在预先记录的顺序中交替先后。每次从 fixture 创建新环境，不沿用前一次答案、产物或隐式历史；独立 HOME、临时目录和可写缓存，依赖可从校验身份的只读缓存复制。记录准备时间、任务时间与评分时间，网络/模型时间和本地开销能分则分，不能分则说明。等待用户不混算为模型活跃时间。

进入判定的耗时、调用次数与用量须来自可信 runner、宿主 provider 入口或独立检查的实际观测；候选 runtime 自报的数据仅作核对材料，不能独自证明自身更快或更便宜。复用 #5 的尝试身份与存储，不另建日常用量账本；观察不完整则保留缺失，相应指标不参与改善判定。

纯文案、无行为变化的精确去重采用一致性/加载路径检查；确定性 bug 用真实回归检查；本地启动、内存、体积或查询瓶颈用对应基准。只有需要判断 prompt/skill/策略的行为或模型成本/延迟变化时才 fresh 对照，不要求每次 improve 重跑全量。历史重评分只回答评分问题，不能代替新策略执行。

## 一个经过验证的 eval 隔离边界

普通 coding 继续遵循 ADR-0001。eval 的额外边界只服务本票受控任务；记录于 [ADR-0003](../adr/0003-eval-isolation-and-evidence-boundary.md)。首版选择一种能满足下列合同的现成隔离能力，通过公开执行环境接口接入；不自研通用沙箱，不先做多后端抽象。具体实现机制是待验证的工程选择，未获得行为证据前不能称为落实，也不能让正式评估静默降级成本机 shell。

可信的外层 runner 持有计划、原始 fixture、评分规则、隐藏预期值及报告；被测执行版本及其工具、依赖、产物都在受限侧。即使候选修改了 runtime，也不能取得外层 runner 的控制权或自行写入可信评分结论。

受限侧只能访问为该 trial 提供的输入、只读运行依赖与独占可写空间。不可访问宿主 HOME/密钥、其他 trial、原始评分资产、历史答案、runner 的进程控制通道或可写共享 Git 元数据；默认不提供任意网络或宿主控制 socket。模型访问由可信宿主按预算中介，复用已有 provider 入口，密钥不交给被测代码；不因此要求另设常驻代理服务。依赖事先准备，额外网络需求须进入计划。目录、prompt、环境变量清理和执行前后 hash 检查都不能单独充当这项权限保证。

评分前停止并确认该 trial 的执行及子进程结束，固定最终产物。导出只接受声明范围内的普通文件，不跟随指向外部的链接，不执行导出内容，也不把候选写出的“通过”日志当作评分结果。需要运行产物时，在同样受限的评分执行区进行；不能把不可信产物放入拥有宿主权限的 grader 进程执行。隐藏预期值留在可信侧比较，不挂载给被测代码；公开测试可以给候选查看，但通过判定使用固定的规则和实际产物，不采信候选改写的测试。

隔离预检及实现验证须覆盖越界读写、隐藏答案、共享目录/进程/网络通道、残留进程和评分阶段执行。已验证阻断一次越界访问时，保留尝试及其失败路径；是否违反任务约束按预定 grader 判断。发生实际越界、污染或不能确认边界有效时，相关 trial 标记无效，停止后续受影响试次，不据此判改善。隔离不可用的诊断模式必须显式区分，且不得向不受保护的执行暴露真实隐藏资产或凭据。

## 失败、重试与预算

不增加“重跑到成功”的策略。默认 runner 不自动重开失败 trial；请求层重试必须可限量、纳入计划并计入同一 trial 的用量和时间。无法落实上游内部尝试上限时，在计划中明确限制，不能宣称每个 HTTP attempt 已精确受控。fresh rerun 是新 trial，原 trial 保留；补跑及其预算若未在原计划中授权，另行决定。

| 情况 | 必须保留的结果与后续行为 |
| --- | --- |
| 模型称完成，实际检查不通过 | 保存产物与检查失败；不判成功。 |
| 任务/工具错误或超时 | 保存执行失败/超时与可取得产物，不偷换为一次重试后的通过；已固定可核验结果可另行评分，但完成要求仍按既定规则处理。 |
| 用户取消、需求变更、预算停止 | 分别记录原因；未执行项仍在计划内，不能删除或算已通过；不直接推断为模型能力失败。 |
| 基础设施/模型服务错误 | 计入实际完成率、时间和成本，单列原因；不把偶发网络失败直接归因于候选策略。 |
| grader 崩溃或证据缺失 | 标记无法评分/证据不足，不将其等同于候选的确定失败或成功。 |
| 隔离失效、评分资产变更、初态不符 | 标记无效及原因，不进入有效改善证据；受影响范围不明时整批不能判改善。 |
| 进程中断、副作用未知 | 沿用 #3 的恢复核对，禁止为了补齐报告自动续跑。新执行保留新的事实；恢复不能放宽版本、隔离或预算约束。 |

首版顺序执行使预算检查保持简单：开始新 trial、请求、重试或自动 compaction 前检查剩余额度和时限，限制可控制的最大输出与调用次数；超时/取消停止放行并终止受管执行。重启不重置已用额度或计划截止时间。在途请求可能已计费，取消不是退款或账单停止证明。无法确认残留执行停止时不得复用空间或启动受影响的下一试次。

用量包括 baseline、candidate、失败/重试、compaction 和评分产生的调用；分析、评估、日常 coding 分开归属，再列总开销。若已知用量加上可证明的在途最大保留额能约束预算，可按余额继续；未知用量且无可靠上界时暂停新请求。价格是带版本与时间口径的估算，不能当成账单硬上限；实际账号硬限额如存在可作为外部补充，不能假定已设置。磁盘原文写入失败按 #5 受控停止，不以删日志换取继续运行。

## 最小判定规则

每份报告分开给出任务达标、效果结论及适用范围；“检查通过”不会自动变成“优化有效”。先保护正确性、用户约束和必要验证，再比较主要目标；不使用综合分把错误与成本抵消。改善结论只适用于声明的案例、版本与环境。

确定性直接检查或基准可据实际证据给出限定范围的修复/改善结论，不要求额外 coding A/B。随机模型行为须按计划重复，不能从单次成功推断改善或稳定性；首版不承诺总体显著性，不引入统计平台。需要的次数和实际有意义的变化阈值，在批次执行前声明；没有校准依据时可先做有预算的诊断，不能看完结果再改门槛。重复一次分析计划、扩大样本或反复搜索候选都需保留原批次身份，不能只挑获胜批次。

采用保守的逐案例、逐配对规则作为首版可逆默认值：主目标案例的差值记为 d，统一为正表示更好，计划预先设最小有意义变化量 δ > 0；各软性保护指标另设最大可接受退化量，正确性/授权等硬约束无退化容忍。保存原始值与计算口径；改善要求每个主目标配对 d ≥ δ，软性目标退化要求每个主目标配对 d ≤ -δ，无明显差异要求每个主目标配对 -δ < d < δ。回归保护案例无需产生正收益，但必须通过保护规则。只看总体平均值可能掩盖某一案例退化，因此不能替代逐案例检查。

| 结论 | 触发条件 |
| --- | --- |
| 改善 | 所有计划试次完成、边界/评分/证据有效；候选满足硬约束和必要验证，保护指标均在事先容忍范围内；各相关重复配对的主要指标都达到事先设定的改善量。成本/延迟改善只在两侧任务效果都达标且口径完整可比时成立。标注“仅本批已测范围”，不声称总体或未来稳定收益。 |
| 退化 | 有有效可比证据表明候选相对 baseline 出现新的硬约束或正确性失败；可立即停止并报告具体回归，无需烧完剩余预算。软指标退化须完成有效比较，主要目标一致越过退化界限，或某项保护指标在对应案例的重复配对中一致超过预定退化容忍度；其余指标即使变好也不能抵消保护项退化。 |
| 无明显差异 | 全部计划完成且有效，硬约束与保护项通过，每个配对的主要差值都落在预先声明的无实质差异区间内。只表示本批未见有意义差异，不证明总体等价。 |
| 证据不足 | 计划未完成、无法有效评分/配对、隔离无效、相关费用或版本/环境信息不足、没有预定阈值、只有一次随机试验，或重复结果方向不一致而无法满足上述规则。可以报告已观察到的变化，不得包装成改善或无差异。 |

判定顺序先看已证实的退化，再看改善、无明显差异，其余为证据不足。任何已观察到的硬约束失败都使候选不达标，可以停止，不能因其他项缺失而消失；若不能证明为候选新增，则报告不达标及效果证据不足，不凭空归因成退化。涉及污染的证据不能用于归因。两侧同样未达标可以报告失败情况和差值，但不能靠失败得更便宜判效率改善。baseline 已失败而 candidate 达标可支持对应任务的修复证据，仍须满足计划中的相关回归与重复条件。

部分改善、部分退化或重复间相互矛盾时，展示每项结果；不能以精选子集给整批贴“改善”。软指标门槛可待基线校准，本票不发明统一百分比、token 数或货币额度；数值未定的批次不能进入对应正式判定。这保留“证据不足”这一正常结果，不要求每次验证选出赢家。

grader 修改单独版本化，保留旧判断；仅评分规则变化时，对两侧保存的相同产物重评分即可。若改变任务、初态、环境或执行行为，须新建可比试验；候选和 grader 同时变更的结果不能用于证明原候选改善。旧规则发现错误的批次标注结论受影响，不能悄悄覆盖。

## 报告、验收与交接

报告至少包含计划身份、版本/初态/评分规则、隔离状态、任务覆盖、结论与局限，并列出所有计划 trial 的执行状态、outcome/评分引用和原因。两侧分别显示计划数、已启动数、已完成数、可评分数，并列出有效配对数；“已完成”指正常执行结束，不包括错误、超时或取消，也不等于检查通过。“可评分”要求边界和证据有效且 grader 产生确定判断，可以包括被明确判失败的错误/超时试次；污染或 grader 故障不计入该数，但仍保留在计划总数及对应原因中。

任务检查通过率为通过数/可评分数，完成率为已完成数/计划数，验证覆盖率为可评分数/计划数；分母为零显示不适用，不写成 0% 或 100%。全部同时给出数量，不把缺失项藏在百分比后；模型/工具失败与基础设施、取消等原因分组列出。日常任务的历史统计继续沿用 #5 的分层和缺失语义，不能与受控 eval 混成一个成功率。

耗时与费用同时展示总消耗及可比配对差异，保留失败、缺失和未归属成本；不能只报成功样本的便宜结果。计划、outcome、评分修订和所需 fixture/版本内容按 #5 固定保留，清理保护这些依赖；允许读取旧结论但证据已缺失时必须说明不可重查。数据集与报告可以只是本地版本化文件，不新增数据集管理服务。

实现阶段以以下行为作为最小验收入口，优先扩展已有检查，不要求为每项新建测试框架：

1. 同 runtime 的两侧从一致初态启动；上一 trial 的文件、历史和进程不会进入下一试次，评分资产读取/修改及宿主越界被实际阻断。
2. 固定计划中的失败、超时、取消、预算停止和未运行项都保留；首次失败不会被补跑覆盖；用量不双计、unknown 不归零。
3. 候选更便宜但检查失败、部分任务退化、只有一次成功、grader 故障及评分资产污染时，不能得出改善；完整接近结果与缺数据分别得到无明显差异和证据不足。
4. 模型调用、重试、compaction 和评分成本共同受预算约束；有效授权不重复询问，扩大范围才重新决定；在途未知及原文写盘失败会停止新工作。
5. grader 变更能保留旧判断并对两侧一致重评分；候选不能用自己改过的规则证明改善。
