## Change and limits

- Existing `runRestricted` and explicit selected-build child output now retain raw Buffer bytes before UTF-8 decoding. An event crossing the output threshold is retained in full; both pipes are then destroyed to stop acquisition. Existing output-limit/timeout/cancel and VM stop/inspect/delete/absence behavior remains.
- Acquisition is bounded per stream by its configured cap plus the first delivered event crossing that cap. Fixed 64 KiB blocks bound metadata growth even if the OS delivers tiny chunks. This is bounded acquisition followed by durable fixed-block persistence, not an unlimited stream collector. In addition to acquired bytes, encoding, text projection and JSON serialization use bounded constant-factor copies.
- Product eval runtime/grader, improve checks/build/startup and explicit child launch persist ordered `{sha256,bytes}` blocks in ordinary Evidence objects. `execution.output` facts expose every direct block reference to existing fixation/retention. Existing object range reads verify hashes while returning at most 16 KiB per page.
- `stdout`/`stderr` are UTF-8 projections. `improve.check` stores a 16 KiB-per-stream preview plus `executionRef`; exact raw bytes remain in ordered block references. `executionRef` retains the existing larger bounded text projection. JSON escaping can expand the fixed maximum roughly sixfold (about 54 MiB for the maximum 8 MiB stdout plus 1 MiB stderr projections); the Evidence fact limit is separate from object size. Object-range reads do not load that whole object.
- The deterministic maximum-configured test retained stdout 8,388,609 bytes and binary stderr 1,048,576 bytes; 129 + 16 blocks. The output fact was 13,816 bytes; the inline check fact 46,699 bytes; the execution object 9,450,921 bytes for those exact inputs. These are content-size observations, not measured peak RSS claims.
- Selected child launch stops pipe reads immediately on controlled stop, waits for child close, then reacquires the data-root owner before persisting output. It does not contend with the child by opening Evidence while the child may own the same root.
- Raw block references replace acquired base64 blocks only after all objects and the output receipt are durable. Persistence failure throws and does not publish retained completeness or replay the operation. Existing teardown facts remain in the restricted execution outcome. Failed output/start receipts, cancellation and ignored SIGTERM are tested.
- All completeness claims concern data actually delivered to the host's `data` events. Bytes still inside a VM, process, pipe or provider after destruction were not acquired; their size/content remains unknown. `sourceEnd` describes local pipe observation, not full remote output or task acceptance.
